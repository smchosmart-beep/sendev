## 문제 진단 (재현 완료)

에디터 직렬화/렌더링 자체는 정상입니다. 실제 편집기에서 만든 마크다운을 그대로 react-markdown 파이프라인에 넣어 검증한 결과, **굵게+색상+밑줄 모든 조합이 올바르게 중첩되고 `<u>` 태그도 항상 짝이 맞게** 출력됐습니다. (예: `<span style="color:#e11d48"><strong><u>빨강굵게밑줄</u></strong></span>`)

### 진짜 원인: CSS 레이어 우선순위

글자색은 `<span style="color:...">` 인라인 스타일로 적용됩니다. 굵게를 적용하면 구조가 `span > strong > 글자` 가 되는데, 본문 영역이 쓰는 Tailwind 타이포그래피 클래스 `prose-strong:text-foreground` 가 `strong` 에 검은색(foreground)을 강제로 다시 칠합니다. `strong` 이 글자에 더 가깝기 때문에 바깥 `span` 의 색을 덮어써서 **검게** 보입니다.

이미 `styles.css` 에 이를 막는 규칙(`span[style*="color"] strong { color: inherit }`)이 있지만, 이 규칙이 `@layer components` 에 있고 `prose-*` 유틸리티는 그 뒤 순서인 `@layer utilities` 에 있어서, **나중 레이어가 이겨버려 무효화**되고 있습니다. 그래서 "굵게 안 하면 색 정상, 굵게 하면 검정"이 됩니다.

### 밑줄 "오류"에 대해

새로 작성·저장하는 글은 직렬화/렌더링 모두 정상(검증 완료)입니다. 예전(직렬화 버그 수정 전)에 저장된 글에는 깨진 `</u>` 마크업이 데이터로 남아 있어 그 글을 열면 계속 깨져 보입니다. 이런 글은 **편집 → 다시 저장** 하면 정상화됩니다. (자동 일괄 정리는 위험하므로 안내로 처리)

## 적용할 변경

### 1. `src/styles.css` — 색상 상속 규칙이 prose 유틸리티를 이기도록 수정
- 색 입힌 span 내부의 `strong`, `em`, `code`, `a`, `u` 가 색을 상속하도록 하는 규칙을 `@layer utilities` 로 옮기고(또는 그 안에 동일 규칙 추가) 선택자 특이도를 prose 규칙보다 높게 유지.
- 에디터(`.tiptap-editor`)와 본문(`.post-content`) 양쪽 모두 적용.
- 이렇게 하면 굵게/기울임/밑줄/코드/링크가 걸린 색상 글자도 지정한 색을 유지합니다.

### 2. 검증
- 미리보기에서 색상+굵게, 색상+밑줄, 색상+굵게+밑줄 조합을 직접 작성·저장·조회하여 색이 유지되고 밑줄이 정상 표시되는지 확인.

### 3. `src/routes/_main.guide.tsx` — 가이드 갱신
- 서식 안내에 "색상은 굵게/밑줄과 함께 써도 유지된다", "예전에 깨져 보이는 글은 편집 후 다시 저장하면 고쳐진다" 내용을 반영.

## 기술 메모
직렬화는 그대로 두고(이미 균형 잡힌 출력 확인), 문제는 순수 표현(CSS) 레이어 우선순위입니다. 따라서 수정 범위는 `styles.css` 의 색상 상속 규칙과 가이드 문서로 한정합니다. 비즈니스 로직/DB 변경 없음.
