## 목표
관리자 대시보드의 **"사용자 프로필" 탭**을, 코드에 박힌 `sendev33`로는 접근하지 못하게 하고 시스템 관리자만 아는 별도 비밀번호 `duck3811`로만 열리도록 한 단계 더 잠급니다. 이 비밀번호는 **코드 어디에도 남기지 않고** 서버 비밀(Lovable Cloud secret)로만 저장·검증합니다.

## 핵심 방식
- `duck3811`을 서버 비밀 `PROFILE_ADMIN_PASSWORD`로 저장(코드/깃에 평문 없음).
- 비밀번호 검증은 **서버 함수에서만** 수행. 브라우저는 입력값을 서버로 보내 `{ ok: true/false }`만 받습니다(비밀값은 클라이언트로 절대 내려오지 않음).
- 검증 통과 시 `sessionStorage`에 별도 플래그를 저장해 해당 세션 동안 프로필 탭 접근 허용(기존 관리자 게이트와 분리된 키 사용).

## 변경 사항

### 0. 서버 비밀 등록
- `add_secret`로 `PROFILE_ADMIN_PASSWORD` 요청 → 사용자가 보안 폼에 `duck3811` 입력. (대화/코드에 값 미노출)

### 1. 서버 함수 (`src/lib/platform.functions.ts`)
- `verifyProfileAdmin({ password })` 추가:
  - `process.env.PROFILE_ADMIN_PASSWORD`와 입력값 비교 → `{ ok: boolean }` 반환.
  - 비밀이 설정되어 있지 않거나 빈 입력이면 `ok: false`.
  - 비밀값 자체는 절대 반환하지 않음.

### 2. 프로필 관리 페이지 (`src/routes/admin.profiles.tsx`)
- 컴포넌트 진입 시 별도 비밀번호 게이트를 먼저 렌더링.
  - 기존 관리자 인증 화면과 유사한 UI(자물쇠 아이콘, 한글 입력 차단, 영문 비밀번호).
  - 입력값을 `verifyProfileAdmin` 서버 함수로 검증.
  - 통과 시 `sessionStorage`의 전용 키(예: `profile-admin-granted`)에 플래그 저장 후 관리 UI 표시.
  - 실패 시 에러 메시지.
- 이미 통과한 세션이면 게이트를 건너뜀.

### 3. 탭 안내(선택)
- "사용자 프로필" 탭에 잠금 아이콘 등으로 추가 인증이 필요함을 시각적으로 표시(기능 영향 없음).

## 기술 메모
- `duck3811`은 `add_secret`를 통해서만 입력되며, 소스/마이그레이션/대화 어디에도 평문으로 남기지 않습니다.
- 검증이 서버에서 이뤄지므로, 클라이언트 번들을 뜯어봐도 비밀번호를 알 수 없습니다(기존 `sendev33`처럼 코드에 노출되는 방식과 다름).
- 기존 대시보드 진입(`sendev33`)은 그대로 두고, 프로필 탭에만 2차 잠금을 추가합니다.
