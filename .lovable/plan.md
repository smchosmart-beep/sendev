# 산출물 공정 평가: 랜덤 순서 + 평가완료 표시

산출물 게시판에서 ① 사람마다 다른(기기별 고정) 랜덤 순서로 산출물을 보여주고,
② 본인이 평가를 완료한 산출물 카드에 "평가 완료" 배지를 새로고침·재방문 후에도
유지되도록 표시합니다. A·B 보완사항(SSR 하이드레이션 안전 처리, 쿼리 안정화)을
반영했습니다.

## 동작 흐름

```text
[산출물 게시판]
  ├─ 산출물 카드 (기기별 고정 랜덤 순서)
  │     └─ 내가 평가한 카드 → "✓ 평가 완료" 배지
  └─ 순서는 새로고침해도 동일, 사람(기기)마다 다름
```

## 구현 내용

### 1. 기기별 고정 랜덤 순서
- `localStorage`에 영구 시드 저장(`sendev:order-seed`). 없으면 최초 1회 생성.
- mulberry32 PRNG 기반 `seededShuffle` 유틸로 `projects` 배열을 결정적 셔플.
- 같은 기기 = 항상 같은 순서, 다른 기기 = 다른 순서, 새로고침해도 유지.

### 2. "평가 완료" 배지 (영구 표시)
- 평가자 식별은 기존 닉네임(`sendev:nickname:{slug}`) 재사용.
- 서버 함수 `listMyReviewedPostIds`(닉네임으로 reviews 조회) 추가.
- 게시판에서 `useQuery`로 내가 평가한 postId 목록을 받아 `ProjectCard`에 배지 표시.
- 평가 제출 성공 시 해당 쿼리를 무효화해 즉시 반영(재방문/새로고침 후에도 DB
  기준으로 유지되므로 영구 표시).

### A. SSR 하이드레이션 안전 처리 (보완)
- `localStorage`(시드·닉네임)는 서버에서 접근 불가하므로 SSR 시점엔 원본 순서를
  그대로 렌더링하고, 클라이언트 마운트(`useEffect`) 이후에 셔플 순서를 적용.
- 이를 통해 서버/클라이언트 렌더 불일치(하이드레이션 경고)와 레이아웃 깜빡임 방지.
- 배지도 닉네임 확정(클라이언트) 이후에만 표시.

### B. 쿼리 안정화 (보완)
- `listMyReviewedPostIds` 결과를 정렬해 반환 → 쿼리 키/데이터 안정화로 불필요한
  리렌더·리페치 방지.
- 쿼리 키는 `["my-reviews", slug, nickname]`로 닉네임 없을 땐 비활성(`enabled`).

## 기술 메모
- 변경 파일: `src/routes/_main.board.$slug.index.tsx`(셔플·배지 UI),
  `src/lib/platform.functions.ts`(`listMyReviewedPostIds`),
  `src/lib/series.ts` 또는 새 유틸(`seededShuffle`, 시드 헬퍼).
- 서버 비용: 셔플은 전부 클라이언트 처리 → 비용 영향 없음. 추가 쿼리는 닉네임당
  가벼운 단건 조회.
- 기존 기능 영향 없음: 링크 시리즈 묶음/다른 게시판 정렬 로직 미변경, 산출물
  섹션에만 적용.
