# 출력 보기 블록 상태를 3단계로 구분

## 문제
새 활동기록 글을 등록하면 아무것도 쓰지 않았는데도 `09 제작자와 라이선스`가
"작성됨"으로 표시됩니다. 글을 만들 때 작성자가 팀원으로 자동 등록되는데,
09번 블록이 "팀원이 1명이라도 있으면 작성됨"으로 판정하기 때문입니다.

또한 현재는 작성됨/미작성 2단계뿐이라, 일부만 채운 블록도 "작성됨"으로 보입니다.

## 개선 내용
9개 블록 각각의 상태를 3단계로 구분합니다.

- **미작성**: 그 블록에 해당하는 항목이 하나도 채워지지 않음
- **작성중**: 일부 항목만 채워짐
- **작성완료**: 그 블록의 핵심 항목이 모두 채워짐

블록별 판정 기준(핵심 항목):

| 블록 | 핵심 항목 |
| --- | --- |
| 01 프로젝트명과 한 줄 설명 | 서비스 이름, 한 줄 소개 |
| 02 대표 화면과 링크 | 대표 이미지, 배포 주소, GitHub 주소 |
| 03 최종적으로 해결한 문제 | 문제, 해결 방법 |
| 04 핵심 기능 | 기능 행 1개 이상(작성완료는 2개 이상) |
| 05 사용 흐름과 사용 방법 | 사용 흐름 행 1개 이상 + 사용 환경 |
| 06 기술 스택·실행 | 화면·서버·AI·저장소·배포 중 3개 이상 + 사용 방법 |
| 07 작동 범위·한계·다음 계획 | 확인한 범위 + 한계 1개 + 계획 1개 |
| 08 교육 현장 주의사항 | 개인정보 처리 여부, 예상 위험, 위험 완화, 태도 점검 |
| 09 제작자와 라이선스 | 제작자·담당 정보(또는 소속/역할이 입력된 팀원) + 코드 라이선스 |

09번은 자동 등록된 작성자 이름만 있는 상태를 "미작성"으로 봅니다.

상단 요약 문구도 "9개 중 N개 작성완료 (M개 작성중)" 형태로 바꾸고,
배지 색은 미작성=회색, 작성중=노란/주황 계열, 작성완료=기본 강조색으로 표시합니다.

## 기술 세부
- `src/lib/record-readme.ts`: `PublicReadmeBlock`에 `status: "empty" | "partial" | "done"`
  필드를 추가하고, `getPublicReadmeBlocks`에서 항목별 채움 개수로 상태를 계산합니다.
  기존 `filled` 필드는 `status !== "empty"`로 유지해 다른 사용처가 깨지지 않게 합니다.
- `src/components/RecordOutput.tsx`: 배지 문구·색상과 요약 문장을 3단계로 갱신합니다.
- README 본문 생성(`buildPublicReadme`)과 저장 로직은 변경하지 않습니다.
- `src/routes/_main.guide.tsx`의 활동기록 출력 보기 설명에 3단계 상태 안내를 추가합니다.
