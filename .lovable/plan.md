# 비밀번호 단일화 (닉네임 비밀번호로 통합)

## 목표
글·댓글마다 따로 받던 "수정·삭제 비밀번호"를 없애고, **닉네임 비밀번호 하나로** 작성·수정·삭제·평가를 모두 처리한다. 익명 작성은 제거하여 모든 글·댓글에 닉네임(+비밀번호)을 요구한다.

## 동작 방식 (변경 후)
- 글/댓글을 쓰려면 **닉네임 + 닉네임 비밀번호**가 필수.
  - 닉네임을 처음 쓰는 경우: 비밀번호를 두 번 입력해 등록(기존과 동일).
  - 이미 등록된 닉네임: 비밀번호 한 번 입력해 본인 확인.
- 글/댓글을 수정·삭제할 때: 그 글 작성자의 **닉네임 비밀번호**를 입력 → 작성자 프로필에 저장된(해시) 비밀번호와 대조.
- 관리자 마스터 비밀번호는 기존처럼 모든 글/댓글에 대해 통과(운영 백업용).
- 기존에 만들어진 옛 글/댓글(평문 수정·삭제 비밀번호만 있는 경우)은 호환을 위해 그 비밀번호로도 계속 인증 가능(폴백).

## 서버 변경 — `src/lib/platform.functions.ts`
1. **createPost**: `editPassword` 입력/저장 제거. 일반 글은 작성자(닉네임) 필수, `ensureNicknameOwnership`로 본인 확인(기존 유지). 공지는 기존대로 운영진/관리자.
2. **checkPostPassword**: 검증 로직 변경
   - 마스터 비밀번호면 통과(유지).
   - 글의 작성자 닉네임을 찾아 `user_profiles.nickname_password`(해시)와 입력값 해시 비교.
   - 옛 글 호환: 위가 없으면 기존 `edit_password` 평문 비교로 폴백.
3. **createComment**: `editPassword` 제거, 작성자 닉네임 필수(익명 기본값 제거), `ensureNicknameOwnership` 적용.
4. **deleteComment**: 댓글 작성자의 닉네임 비밀번호로 검증(+마스터, +옛 댓글 평문 폴백).
5. `edit_password` 컬럼 자체는 옛 데이터 호환을 위해 그대로 둔다(스키마 변경/마이그레이션 없음).

## 클라이언트 변경
- **새 글 폼 4종** (`new-general`, `new-link`, `new-project`, `new-question`):
  - "수정·삭제 비밀번호" 입력칸과 관련 검증/전송 제거.
  - 작성자(닉네임) 필수화, 닉네임 비밀번호(+최초 등록 시 확인) 유지.
- **상세 페이지** `_main.board.$slug.$postNo.tsx`:
  - 댓글/답글 작성 폼(2곳): "삭제용 비밀번호" 칸 제거, 닉네임 비밀번호로 통합. 작성자 필수화("익명" 안내 문구 수정).
  - 글 수정·삭제, 댓글 삭제 확인창: 입력 라벨/안내를 "닉네임 비밀번호"로 변경하고 닉네임 비밀번호를 전송.

## 가이드 업데이트 — `src/routes/_main.guide.tsx`
- "글 수정·삭제 비밀번호 vs 닉네임 비밀번호" 섹션을 **단일 비밀번호** 설명으로 재작성.
- "비밀번호를 두 번 입력" 안내를 "닉네임 최초 등록 시에만 두 번 확인"으로 정리.
- 익명 작성 관련 문구 제거.

## 기술 메모
- DB 마이그레이션 없음(기존 `edit_password` 컬럼 유지, 신규 글은 미사용).
- 평문 비밀번호 저장이 사라져 보안상 더 안전해진다.
- 옛 글/댓글도 기존 비밀번호로 계속 수정·삭제 가능(폴백 유지).
