# 닉네임 비밀번호 확인 + 관리자 삭제/초기화 오류 수정

## 진단 요약
- **평가/댓글 카드 확인칸 없음**: 산출물 평가 폼, 댓글 작성 폼, 답글 작성 폼에 닉네임 비밀번호 "확인" 입력이 없음.
- **새 글 확인 대상 잘못됨**: 새 글 작성 4종(`new-general/question/project/link`)이 닉네임 비밀번호가 아니라 **수정·삭제 비밀번호**를 두 번 입력받고 있음.
- **초기화/삭제 버튼 무반응(오류)**: `admin.profiles.tsx`가 브라우저 `window.confirm()`을 사용하는데, 미리보기(샌드박스 iframe)에서는 `confirm()`이 차단되어 항상 false 반환 → 뮤테이션이 실행되지 않음. 서버 함수 자체는 정상. (프로젝트 내 `confirm()` 사용처는 이 파일뿐)

## 변경 내용

### 1. 닉네임 비밀번호 확인칸 추가 (최초 등록 시에만)
"처음 닉네임을 등록할 때"(`hasStored`가 false, 평가 카드는 저장된 비밀번호 없음)에만 "닉네임 비밀번호 확인" 입력을 노출하고, 두 값이 다르면 제출 차단 + 안내 문구 표시.
- `_main.board.$slug.$postNo.tsx`
  - 산출물 평가 폼: `nicknamePasswordConfirm` 상태 추가, 저장된 비밀번호가 없을 때 확인칸 표시, 제출 검증.
  - 댓글 작성 폼(최상위): 동일.
  - 답글 작성 폼(`ReplyComposer`): 동일.

### 2. 새 글 작성: 확인 대상을 닉네임 비밀번호로 정정
4개 새 글 파일에서:
- 수정·삭제 비밀번호 "확인" 입력 + 관련 상태(`editPasswordConfirm`) + 검증 제거.
- 닉네임 비밀번호 "확인" 입력(`nicknamePasswordConfirm`, `!hasStored`일 때)과 검증은 유지.

### 3. 관리자 삭제/초기화 동작 복구
`admin.profiles.tsx`의 `window.confirm()` 4곳(닉네임 비밀번호 초기화, 프로필 삭제, 배지 삭제, 아이콘 규칙 삭제)을 shadcn `AlertDialog` 기반 확인 모달로 교체해 미리보기에서도 정상 동작하도록 함. 대상 항목/문구를 상태로 들고 "확인" 클릭 시 해당 뮤테이션 실행.

### 4. 가이드 갱신
`/guide`(`_main.guide.tsx`)에서 닉네임 비밀번호 확인 입력 동작 설명을 "평가·댓글·새 글 모두, 최초 등록 시 두 번 입력"으로 정정하고, 수정·삭제 비밀번호는 한 번만 입력한다는 점을 반영.

## 기술 메모
- 데이터베이스/스키마 변경 없음.
- `AlertDialog` 컴포넌트는 이미 `src/components/ui/alert-dialog.tsx`에 존재.
- 검증은 클라이언트 UX용이며, 서버 인증(비밀번호 일치/관리자 권한)은 기존 서버 함수가 그대로 담당.
