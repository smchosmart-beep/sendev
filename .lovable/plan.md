## 목표

관리자 **카테고리 목록**(`/admin/categories`)을 일반 게시판 네비게이션처럼 폴더 단위로 정리합니다.

1. 폴더(그룹) 카테고리 아래의 **하위 카테고리는 폴더를 펼쳤을 때만** 표시.
2. 위/아래 위치 변경은 **같은 폴더 안(같은 부모)에서만** 가능.

## 현재 동작

- `visibleCategories`를 한 줄짜리 평면 목록으로 그대로 나열 → 폴더와 하위가 섞여서 보임.
- 위/아래 이동(`moveCategory`)이 **같은 탭(tabGroup) 전체**를 기준으로 순서를 바꿔, 폴더 경계를 무시하고 이동됨.
- 이동 버튼은 `listFilter !== "all"`(특정 탭 필터 시)에만 노출.

## 변경 사항

파일: `src/routes/admin.categories.tsx` (UI/표현 로직만)

### 1. 접을 수 있는 폴더 트리로 목록 재구성
- `expandedFolders` 상태(`Set<string>`) 추가 — 펼쳐진 폴더 id 집합.
- `visibleCategories`를 다음 순서로 묶어 렌더:
  - 부모가 없는 항목(최상위 폴더 + 폴더에 속하지 않은 일반 카테고리)을 `sortOrder` 순으로 출력.
  - 폴더 행에는 좌측에 펼침/접힘 토글(Chevron) 아이콘 + 해당 폴더의 하위 개수 표시.
  - 폴더가 펼쳐진 경우에만, 그 폴더를 부모로 갖는 하위 카테고리를 `sortOrder` 순으로 **들여쓰기(indent)** 하여 폴더 바로 아래에 출력.
- 탭 필터(`listFilter`)가 적용되면 해당 탭 항목만 동일 규칙으로 묶어 표시.

### 2. 위치 변경을 같은 폴더로 제한
- `moveCategory`의 형제 그룹 계산을, 현재 "같은 tabGroup 전체"에서 **"같은 tabGroup + 같은 parentId"**로 변경:
  - 최상위 항목끼리만 서로 이동, 같은 폴더의 하위끼리만 서로 이동.
- 위/아래 버튼의 비활성화(disabled) 판정도 이 형제 그룹 기준으로 계산.
- 이동 버튼 노출 조건을 같은 폴더 내 형제가 2개 이상일 때 보이도록 정리(현행 `listFilter !== "all"` 제약은 유지하되 그룹 기준만 폴더로 좁힘).

### 3. 가이드 문서 업데이트
- `src/routes/_main.guide.tsx`의 카테고리 관리 설명에, 목록에서 폴더를 펼쳐 하위 카테고리를 보고 폴더 안에서만 순서를 바꿀 수 있다는 점을 한 줄 보완.

## 검증

- 폴더 카테고리를 접으면 하위가 숨겨지고, 펼치면 들여쓰기되어 나타나는지 확인.
- 최상위 항목은 최상위끼리, 폴더 하위는 같은 폴더 하위끼리만 위/아래로 이동되는지 확인.
- 서버 함수(`swapCategoryOrder`) 변경 없이 정상 동작하는지 확인.
