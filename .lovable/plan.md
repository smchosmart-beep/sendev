# 02 문제 정의 과정 — 전용 탭 입력칸이 사라진 문제 수정

## 무엇이 잘못됐나

"그 밖의 문제 정의 메모" 탭에만 추가 버튼을 남기도록 바꾼 뒤,
[22일 팀빌딩·문제 정의 회의], [인터뷰 기록], [인터뷰 후 문제 구체화 회의]
세 탭은 **기록 줄을 만들 방법이 사라졌습니다**. 이 탭들은 저장된 줄이 있어야
입력칸이 그려지는 구조라, 아직 아무것도 쓰지 않은 팀에게는
"아직 등록된 내용이 없어요."만 보입니다.

## 어떻게 고칠까

세 탭은 각각 **정해진 한 벌의 양식**이므로, 줄을 추가하는 개념 없이
탭을 누르면 **바로 그 양식의 입력칸이 펼쳐지도록** 합니다.

- 전용 양식 탭을 열었을 때 그 탭의 기록이 아직 없고 편집 권한이 있으면,
  화면에 **빈 양식 한 벌을 바로 표시**합니다. (내용을 채워 저장할 때
  비로소 실제 기록으로 저장되고, 그냥 지나가면 아무것도 남지 않습니다.)
- 편집 권한이 없는 사람(팀원이 아닌 방문자)에게는 지금처럼
  "아직 등록된 내용이 없어요."만 보입니다.
- 추가 버튼은 기존 요청대로 **"그 밖의 문제 정의 메모" 탭에만** 유지합니다.
- 내용이 하나도 없는 빈 기록은 **README 출력과 사례집 출력에서 제외**해
  빈 항목 제목만 찍히는 일을 막습니다.

## 기술 메모

- `src/components/RecordEditor.tsx`
  - `RowSection`: 선택된 탭에 `PROCESS_SUBTYPE_TEMPLATES` 전용 양식이 있고
    해당 탭 행이 0개이며 `canEdit`이면, 저장되지 않은 임시 행(`id: ""`,
    `subtype: 선택탭`)을 만들어 `RowItem`으로 렌더링. 저장 시 기존
    `onSave`가 신규 생성 경로를 타도록 처리하고, 임시 행에는 삭제 버튼을
    숨김.
  - 추가 버튼 노출 조건(`selectedSubtype === defaultSubtype`)은 그대로 유지.
- `src/lib/record-readme.ts`, 사례집 문서 컴포넌트: 각 행 렌더 전에
  col1~col6이 모두 공백인 행은 건너뛰도록 필터 추가.
- `src/routes/_main.guide.tsx`: 02 단계 설명에 "전용 탭은 탭을 누르면 바로
  양식이 열리고, 그 밖의 메모 탭에서만 줄을 추가한다"는 문장 반영.

서버 함수·DB 스키마 변경 없음.
