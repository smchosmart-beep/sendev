# 03·04 단계에 작성 현황 사이드바 추가 (왼쪽 여백 배치)

내용이 많은 **03 최종 결과물**과 **04 개발·교육적 점검** 단계에, 본문 왼쪽 빈 여백에 떠 있는 "작성 현황" 사이드바를 붙입니다. 블록 목록 클릭으로 바로 이동하고 작성 현황이 한눈에 보입니다. 레퍼런스의 번호 뱃지 + 제목 + 상태 라벨 구조를 따르되, 색·모서리·그림자는 지금 sendev 톤(`rounded-2xl`, `bg-card`, 시맨틱 토큰, 은은한 그림자)을 그대로 씁니다.

## 화면

```text
[ 작성 현황 ]   [ 본문 블록들 (기존 그대로, 폭 그대로) ]
 전체 3/10        01 한눈에 보기
 01 …  작성됨     02 문제와 해결
 02 …  작성중     03 사용과 배포
 03 …  미작성     ...
```

- 넓은 화면(좌우 여백이 충분할 때만): 본문 컨테이너 **왼쪽 여백**에 sticky로 띄웁니다. 본문 폭·레이아웃은 **전혀 바뀌지 않습니다**.
- 여백이 좁아 사이드바가 본문을 가릴 수 있는 폭에서는 자동으로 숨기고, 본문 위쪽 접이식 카드(헤더에 "3/10 작성" 요약)로 대체합니다.
- 항목 클릭 시 해당 블록으로 부드럽게 스크롤하고, 스크롤 위치에 따라 현재 블록이 강조됩니다.


## 각 단계 블록 목록 (실제 편집 화면 기준)

**03 최종 결과물** (10개): 한눈에 보기 / 문제와 해결 / 사용과 배포 / 기술 구성 / 라이선스와 출처 (여기까지는 최종 결과물 카드 안의 필드 그룹) + 핵심 기능 / 사용 흐름 / 현재 한계 / 다음 계획 / 제작자와 담당 (반복행 섹션)

**04 개발·교육적 점검** (8개): 자유 개발 기록 / 바꾼 판단 / 막혔던 순간 / 교사와 학생의 자리 / AI 활용과 확인 / AI 실수 검증 / 입력·전송·저장 / 위험·대응·검증

## 상태 표시

- **미작성**: 해당 블록에 아무 값도 없음 (흐린 회색)
- **작성중**: 일부만 채워짐 (앰버 계열 토큰)
- **작성됨**: 필드가 모두 채워짐 / 행이 1건 이상 (프라이머리 계열)

행 기반 블록은 행 수(`2건`)를, 필드 기반 블록은 채운 칸 수(`3/6`)를 상태 옆에 작게 덧붙입니다.

## 기술 메모

- 새 컴포넌트 `src/components/record/StepSidebar.tsx`: `{ id, no, title, status, meta }[]`와 현재 활성 id를 받아 렌더링. 스크롤 감시는 `IntersectionObserver`, 클릭 시 `scrollIntoView({ behavior: "smooth", block: "start" })`.
- 앵커 id는 카드가 아니라 **`FINAL_GROUPS`의 각 그룹 `div`**와 각 `RowSection` 래퍼에 부여하고 `scroll-mt-24`를 함께 둡니다.
- 배치: 03·04 단계 래퍼를 `relative`로 두고, 사이드바를 `absolute right-full mr-6 top-0 h-full` + 내부 `sticky top-24 w-[240px]`로 왼쪽 여백에 띄웁니다. 본문 그리드·폭에는 손대지 않습니다.
- 노출 조건: 왼쪽 여백은 대략 `(100vw - 1024px)/2`이므로, `1536px` 이상(`2xl:block`, 여백 약 256px)에서만 보이게 하고 그 아래에서는 `hidden` + 본문 상단 접이식 카드로 대체합니다. `_main.tsx`와 라우트 파일은 수정하지 않습니다.
- 상태 계산은 `src/lib/record-progress.ts`에 순수 함수로 분리하고, **편집 블록 기준으로 독립 계산**합니다. `record-readme.ts`의 판정은 README 출력 블록 단위라 경계가 달라 재사용하지 않고, 3단계 구분(`empty`/`partial`/`done`)과 라벨 문구만 동일하게 맞춥니다. 07 출력 보기 배지 로직은 손대지 않습니다.
- 데이터 소스는 이미 로드된 `bundle`과 `final` 로컬 상태뿐이라 추가 서버 요청·쿼리·마이그레이션이 없습니다. 저장 로직에도 손대지 않습니다.
- 사이드바는 인쇄/출력 영역과 무관하므로 `record-output-ui` 계열 클래스와 충돌하지 않게 별도 래퍼로 둡니다.
