## 문제 진단 (재현 완료)

화면의 `상명초등학교</u>` 처럼 `</u>` 가 글자로 새는 현상은 **굵게+밑줄 단어 뒤에 공백 없이 한글이 바로 이어질 때** 발생합니다.

실제 직렬화 결과를 재현하니 마크다운이 이렇게 깨집니다:

```
안녕하세요. **<u>상명초등학교</u**>에 근무하는 ...
```

굵게를 뜻하는 `**` 닫는 기호가 `</u>` 태그 한가운데로 끼어들어 `</u**>` 가 됩니다. 마크다운의 `**`(굵게) 기호는 바로 옆에 한글/구두점이 붙으면 "닫기"로 인정되지 않는 규칙(flanking)이 있는데, 옆에 raw HTML `<u>` 태그가 붙으면서 이 규칙과 충돌해 위치가 어긋나는 것이 원인입니다. (앞뒤로 공백이 있으면 우연히 정상 동작해서 그동안 케이스에 따라 됐다 안 됐다 했습니다.)

## 해결 방법

굵게/기울임을 마크다운 기호(`**`, `*`) 대신 **HTML 태그(`<strong>`, `<em>`)로 저장**하도록 바꿉니다. 밑줄(`<u>`)·색상(`<span>`)이 이미 HTML 태그로 저장되므로, 굵게/기울임도 같은 방식으로 통일하면 기호-태그 충돌 자체가 사라집니다.

수정안으로 모든 조합을 재검증한 결과 정상 출력됩니다:

```
안녕하세요. <u><strong>상명초등학교</strong></u>에 근무하는 ...
<span style="color:#e11d48"><u><strong>빨강굵게밑줄</strong></u></span>뒤
```

화면 렌더링(react-markdown)에서도 `</u>` 누출 없이 굵게+밑줄+색상이 모두 올바르게 표시됩니다.

## 적용할 변경

### 1. `src/components/PostEditor.tsx`
- `@tiptap/extension-bold`, `@tiptap/extension-italic` (코어와 동일한 3.24.0 버전)을 추가.
- StarterKit 설정에서 `bold`, `italic` 을 끄고, 마크다운 직렬화를 `<strong>…</strong>` / `<em>…</em>` 로 내보내도록 확장한 Bold·Italic 확장을 등록.
- 나머지(밑줄·색상·글자크기·이미지·링크) 로직은 그대로 유지.

### 2. 검증
- 미리보기에서 "굵게+밑줄 단어 뒤에 바로 한글" 케이스를 직접 작성·저장·조회하여 `</u>` 누출이 없고 굵게/밑줄/색상이 모두 정상인지 확인.

### 3. `src/routes/_main.guide.tsx`
- 서식 안내에 굵게+밑줄 조합이 정상 동작함을 반영하고, 기존에 깨져 보이는 글은 편집 후 다시 저장하면 고쳐진다는 안내를 유지/보강.

## 참고
- 직렬화 방식만 바뀌므로 기존에 깨진 채 저장된 글은 자동으로 고쳐지지 않습니다. 해당 글은 **편집 → 다시 저장**하면 새 방식으로 정상화됩니다.
- 앞서 적용한 색상 상속 CSS(`!important`) 수정은 그대로 둡니다(굵게+색상 정상 동작 확인됨).
- DB/비즈니스 로직 변경 없음.
