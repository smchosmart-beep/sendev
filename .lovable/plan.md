# 투표 동점 시 결선(재)투표

36개 글 중 12개를 뽑는 투표에서, 경계선(12위) 동점이 생기면 **동점 후보만 대상으로 하는 결선 투표**를 관리자가 열 수 있게 합니다.

## 동작 흐름

1. 관리자가 투표를 열 때 **선발 정원**(예: 12)과 1인당 선택 수를 함께 지정합니다.
2. 마감하면 득표순 정렬 + 순위가 표시되고, 상위 정원 안에 들어온 글에는 **선발 배지**가 붙습니다.
3. 경계선 동점이 있으면 결과 위에 안내가 뜹니다.
   예) `11팀 확정, 남은 자리 1개를 3팀이 동점(4표)으로 다투는 중`
4. 관리자가 **[결선 투표 시작]** 버튼을 누르면
   - 확정된 상위 팀은 그대로 확정 유지
   - 동점 후보들만 결선 후보로 등록
   - 1인당 선택 수를 **다시 지정**(입력칸 기본값 = 남은 자리 수, 필요하면 다른 값으로 변경 가능. 결선 후보 수를 넘을 수는 없음)
   - 상태가 다시 `open`(결선 라운드)으로 전환
5. 결선 중에는 목록이 결선 후보만 보이고 상단에 "결선 투표" 배지가 붙습니다. 1차 표는 지워지지 않고 라운드별로 따로 집계됩니다.
6. 결선을 마감하면 확정 팀 + 결선 통과 팀을 합쳐 최종 12팀이 표시됩니다. 결선에서도 또 동점이면 같은 방식으로 다음 라운드를 열 수 있습니다.
7. 관리자는 **[결선 취소]**로 직전 라운드 표만 지우고 이전 상태로 되돌릴 수 있습니다.

## 투표 자격·규칙

- 1차와 동일: 닉네임+비밀번호 등록자, 본인 글 투표 불가, 저장하려면 정해진 개수를 정확히 선택.
- 결선 참여는 1차 투표 여부와 무관하게 열려 있습니다.
- 결과·작성자는 마감 후에만 공개되는 기존 규칙 그대로 유지합니다.

## 기술 사항

데이터베이스 변경(마이그레이션)
- `categories`에 `vote_seats`(선발 정원, 기본 1), `vote_round`(현재 라운드, 기본 1) 추가
- `votes`에 `round`(기본 1) 추가, 기존 행은 1로 채움. 중복 방지 인덱스를 `(category_id, voter_key, post_id, round)` 기준으로 재생성
- 결선 후보 목록은 `vote_runoff_ids`(jsonb 배열)로 `categories`에 저장. 라운드별 후보와 확정 목록을 함께 보관해 결과 화면에서 재현
- 신규 컬럼만 추가하므로 GRANT 변경은 불필요(기존 테이블 유지)

서버 함수(`src/lib/platform.functions.ts`)
- `setVoteStatus`: `seats` 입력 추가, 새 투표를 열 때 라운드 1로 초기화
- `getVoteState` / `getVoteResults`: `seats`, `round`, `runoffIds`, `lockedIds`, 라운드별 counts 반환
- `startRunoff`(신규, 관리자 전용): 현재 라운드 집계 → 확정 목록과 경계선 동점 목록 산출 → 다음 라운드 오픈. `maxChoices`를 입력으로 받아(미지정 시 남은 자리 수) 1 이상·결선 후보 수 이하로 검증. 동점이 없으면 오류로 거부
- `cancelRunoff`(신규, 관리자 전용): 현재 라운드 표 삭제 후 이전 라운드 `closed` 상태로 복귀
- `submitVotes` / `getMyVotes` / `getVoteRequirement`: 현재 라운드 기준으로 조회·저장, 결선 라운드에서는 후보 목록 밖 글 선택을 서버에서 차단(선택 수 = 남은 자리 수)

프론트(`src/components/VoteSection.tsx`)
- 마감 화면에 순위·선발 배지·동점 안내 배너 추가
- 관리자 컨트롤에 정원 입력, [결선 투표 시작], [결선 취소] 추가
- 결선 라운드에서는 후보만 렌더링, 안내 문구/선택 개수 문구를 라운드에 맞게 표시

문서
- `src/routes/_main.guide.tsx` 투표 게시판 섹션에 정원·결선 투표 규칙 설명 추가

## 부작용 검토

- 신규 컬럼은 모두 기본값이 있어 기존 투표 게시판은 정원=기존 선택 수, 라운드=1로 그대로 동작합니다.
- 추가 폴링·연산 없이 기존 쿼리에 필드만 늘어나므로 서버 비용 영향은 사실상 없습니다.
- 결선 시작/취소는 관리자 비밀번호 검증을 거치며, 1차 표는 삭제하지 않습니다.
