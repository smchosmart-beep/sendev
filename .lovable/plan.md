# 아스트라 코드베이스 전달 + 리팩토링 검수

## 1단계 — 아스트라 전달 자료 준비 (지금)

1. 코드베이스 zip을 만들어 Files에 올린다.
   - 포함: `src/`, `package.json`, `tsconfig.json`, `vite.config.ts`, `components.json`, `eslint.config.js`, `src/styles.css`, `supabase/` 등 소스와 설정 전체.
   - 제외: `node_modules/`, 빌드 결과물, `.git/`, `.env`(키 파일), `bun.lockb`/`bun.lock`은 포함해도 무방하나 용량이 크면 제외, `.lovable/` 내부 메타데이터.
   - 생성은 `/tmp`에서 조립·압축 후 `/mnt/documents/센데브-코드베이스.zip`으로 복사. 압축 전 전체 엔트리 목록을 점검해 제외 대상이 섞이지 않았는지 확인.
2. zip 안에 아스트라 전달 문서(`ASTRA-BRIEF.md`)를 함께 넣는다. 내용:
   - 프로젝트 개요: 한국어 초등 교육 플랫폼(활동기록 도전형/성장형, 나눔, 투표, 관리자).
   - 이미 전달한 11개 금지·주의 규칙(프레임워크 교체 금지, Cloudflare Workers 런타임 제약, 자동 생성 파일 목록, DB 제외, 서버 경계 규칙, RecordEditor/GrowthRecordEditor 저장 로직, 활동기록 필드 다중 동기화 지점, 시맨틱 토큰, 한국어 문구 유지, `bunx tsgo --noEmit` + `bun run build:dev` 검증, 결과물 형식).
   - 결과물 형식 요구: **변경된 파일만 모은 zip + 파일별 변경 이유 1줄 목록**, 파일 경로·이름·폴더 구조 변경 금지.

## 2단계 — 아스트라 수정본 수령 후 적용 + 검수 (사용자가 zip을 가져오면)

1. **엔트리 점검:** zip 목록을 나열해 금지 파일(`src/routeTree.gen.ts`, `src/integrations/supabase/*`, `.env`, `supabase/config.toml`)이 포함됐는지 확인하고, 포함됐다면 현재 파일과 비교해 변경 여부를 판정.
2. **적용:** 변경 파일만 프로젝트에 덮어쓰기(경로·이름 유지 확인). 적용 전 현재 파일을 `/tmp` 백업해 되돌리기 가능하게 유지.
3. **정적 검수:** `bunx tsgo --noEmit`, `bun run build:dev` 통과 확인.
4. **동작 검수(핵심만):**
   - 활동기록(성장형) 저장 → 새로고침 후 값 유지(특히 개인정보 처리 여부, 동료 점검 짝 고정).
   - 활동기록(도전형) 저장 및 README/사례집 출력.
   - 게시판·투표·나눔 화면 정상 렌더링, 콘솔 에러 없음.
   - 하드코딩 색상(`text-white`, `bg-[#...]`)·framer-motion 외 프레임워크 교체 여부 확인.
5. **보고:** 변경된 파일 목록, 아스트라 설명과 실제 diff 대조 결과, 발견된 문제와 수정 여부를 정리해 보고. 문제가 있으면 백업에서 되돌리거나 직접 수정 후 재검증.

## 범위 밖
