# 동료 점검 짝이 다시 열 때마다 바뀌는 문제 수정

## 무슨 일이 일어나고 있나

짝은 배정될 때 기록에 저장되고 있습니다. 그런데 그 직후 화면이 자동 저장을 하면서 "짝 없음" 상태를 다시 덮어씁니다. 그래서 다음에 화면을 열면 저장된 짝이 사라져 있고, 새 짝이 무작위로 다시 뽑힙니다. 피드백을 보낸 뒤에만 유지되는 것처럼 보이는 이유는, 보내기 기록이 별도로 남기 때문입니다.

## 고칠 내용

1. 한 번 배정된 짝은 계속 그 짝으로 유지합니다.
   - 저장된 짝이 있으면 다시 뽑지 않고 그대로 보여 줍니다(지금은 2명이 다 차 있을 때만 유지되어, 후보가 1명뿐인 경우에도 매번 다시 뽑힙니다).
   - 자동 저장이 짝 정보를 지우지 못하게 막습니다. 짝 목록은 화면이 아니라 서버가 관리하는 값으로 취급합니다.
2. 배정 직후 화면 안의 기록에도 짝을 반영해, 탭을 오가거나 새로고침해도 같은 짝이 보이게 합니다.
3. 안내 문구를 사실에 맞게 바꿉니다.
   - 지금: "짝은 무작위로 정해집니다."
   - 바꿈: "짝은 무작위로 한 번만 정해지고, 그 뒤에는 바뀌지 않습니다. 짝의 배포 주소를 열어 보고 돌아와도 같은 짝이 그대로 있습니다."
   - 버튼 아래 안내도 이미 배정을 받은 뒤에는 "이미 배정된 짝입니다. 다시 눌러도 바뀌지 않습니다."로 표시합니다.

## 기술 메모

- `src/lib/record-growth.functions.ts`
  - `getGrowthPeerAssignments`: 재사용 조건을 `review.peer.assigned.length >= 2`에서 `> 0`으로 변경.
  - `saveGrowthRecord`의 review 병합(`merged.peer`): `assigned`는 항상 서버에 저장된 값을 유지하고 클라이언트가 보낸 값은 무시. 저장 스키마의 `peer.assigned`는 남겨 두되 병합에서 제외합니다.
- `src/components/record/GrowthRecordEditor.tsx`
  - 배정 응답을 받으면 로컬 `review.peer.assigned`를 갱신해 화면 상태와 서버 상태를 일치시킴(자동 저장이 더 이상 이 값을 덮어쓰지 않으므로 안전).
  - 안내 문구 두 곳 수정.
- DB 변경 없음. 도전형·나눔·투표 기능은 건드리지 않습니다.
- 이미 짝이 어긋난 채 저장된 기록은, 다음에 배정 화면을 열 때 마지막으로 저장된 짝으로 고정됩니다.

## 확인 방법

짝 배정 → 다른 탭 이동 → 새로고침 → 같은 짝이 그대로인지 확인. 피드백 보내기 전에도 유지되는지 확인.
