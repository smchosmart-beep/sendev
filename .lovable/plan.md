# 성장형 활동기록 작성 폼 개편 (새 HTML 반영)

새로 보내주신 HTML과 현재 구현을 비교해 단계 구성과 입력 항목을 새 버전에 맞춥니다. 이번 작업은 **작성 폼만** 다루고, HTML 안의 '나눔(온라인 갤러리 워크)' 화면은 만들지 않습니다.

## 지금과 달라지는 점

현재: 6단계 (01 나의 프로젝트 · 02 문제와 해결 · 03 결과물 · 04 성장과 점검 · 05 README 출력 · 06 사례집 출력)

새 구성: 7단계

```text
[01 나의 프로젝트] [02 문제와 해결] [03 결과물] [04 검토 및 개선] [05 성찰과 성장] [06 README] [07 성장 사례집]
```

- **04 검토 및 개선**(신설): 자기 점검 → AI 점검 → 동료 점검 3개 탭, 상단에 `n / 3 점검` 표시
- 기존 '04 성장과 점검'은 **05 성찰과 성장**으로 이동(항목은 그대로, 안내문만 새 HTML 문구로)
- **03 결과물**에 `GitHub 저장소 주소` 입력칸 추가, 대표 이미지 안내는 '2MB 이하'로 통일
- 단계 이름을 `06 README`, `07 성장 사례집`으로 변경
- 필수 항목·진행률 기준(01 5개 / 02 3개 / 03 3개 / 05 6개)은 HTML과 동일하게 유지

## 04 검토 및 개선 상세

**1차 자기 점검**
- 체크리스트 6줄(한 줄 소개대로 동작 / 첫 화면 이해 / 핵심 기능 ①②③ / 사용 흐름 1→2→3)을 01~03에 적은 내용을 그대로 인용해 보여 주고 각 줄을 `됨 · 화면만 · 안 됨`으로 선택
- 선택 결과에 따라 '03 완성 상태 제안'(아이디어 / 시연 가능 / 바로 사용 가능 후보)을 안내만 표시(03 값은 자동 변경하지 않음)
- '안 되는 길도 걸어 보기' 6개 관점(정상 / 잘못된 입력 / 경계값 / 상태·저장 / 권한·개인정보 / 실패 상황)을 `확인함 · 문제 있음 · 해당 없음`으로 표시

**2차 AI 점검**
- HTML에 정해진 공통 질문 3개 + 문제 영역별 질문 2개를 순서대로 제시(질문 받기 → 답 입력 → '지금은 답하지 못함' 표시 가능)
- 답하지 못한 질문 수를 세어 표시하고, 오류 대응 5단계 안내(재현 / 증거 확인 / 분류 / 최소 수정 / 재검증)와 수정 프롬프트 복사 버튼 제공

**3차 동료 점검**
- 같은 성장형 게시판의 다른 사람 기록 중 2명을 자동 배정(재배정 버튼 제공, 본인 제외)
- 짝의 프로젝트명·한 줄 소개·핵심 기능·사용 흐름·배포 주소를 보여 주고, `기대한 것 / 실제로 나온 것`을 적어 **보내기** → 상대방의 '내가 받은 피드백'에 실제로 도착
- 받은 피드백은 `오늘 고침 / 다음에 / 고치지 않음`으로 분류

**세 점검 공통 수정 기록**: 고친 것 · 어떻게 고쳤나(전→후) · 고치지 않기로 한 것과 이유 · 분류. '다음에 고침'으로 분류한 항목은 05의 '다음에 보완하고 싶은 것'에 **04에서 가져오기** 버튼으로 이어붙일 수 있습니다.

## 06 README · 07 성장 사례집

- README에 `6. 검토 및 개선`(1·2·3차 수정 내용, 고치지 않기로 한 것)과 GitHub 저장소 줄 추가
- 사례집 지면을 4장 구성으로 재조판: `01 문제와 해결` / `02 결과물` / `03 검토와 개선`(세 점검 + 답하지 못한 질문 수 + 동료가 남긴 말) / `04 성찰과 성장`

## 기술 메모

- 마이그레이션 1건
  - `record_growth`에 `github_url text NOT NULL DEFAULT ''`, `review jsonb NOT NULL DEFAULT '{}'`(자기·AI 점검 응답과 세 수정 기록, 배정된 짝 정보) 추가
  - `record_growth_peer_feedback` 신설: `id`, `post_id`(→posts), `from_post_id`, `from_name`, `expected`, `actual`, `receiver_type text DEFAULT ''`(받은 사람이 정하는 분류), `created_at/updated_at`. 다른 `record_*` 테이블과 동일하게 RLS on + `service_role`만 GRANT, 접근은 서버 함수 경유
- `src/lib/record-growth-schema.ts`: 7단계 메타, 체크리스트/관점/AI 질문 목록, 수정 기록 필드, 새 문구를 모두 여기서 관리(필수·진행률 기준은 유지)
- `src/lib/record-growth.functions.ts`: 저장 필드에 `githubUrl`·`review` 추가, `assignGrowthPeers`(같은 카테고리 기록 중 본인 제외 2명 무작위 배정, 결과는 review에 저장) / `sendGrowthPeerFeedback` / 조회 시 받은 피드백 목록 포함. 자동 저장은 기존과 동일하게 1초 지연 1요청 방식이라 서버 요청량은 늘지 않고, 짝 배정·피드백 전송만 버튼을 누를 때 1회씩 호출됩니다
- `src/components/record/GrowthRecordEditor.tsx`: 단계 배열 확장, `ReviewStep` 하위 컴포넌트(자기/AI/동료 탭) 추가, 03에 GitHub 입력 추가
- `GrowthReadmeOutput.tsx` / `GrowthCasebookDocument.tsx`: 위 출력 변경 반영(인쇄 스타일은 기존 `.casebook-*` 재사용)
- `/admin/records` 성장형 탭의 진행률 계산 기준은 그대로 두고, 04 점검 완료 수(0~3) 열만 추가
- 도전형(활동기록) 코드·데이터는 건드리지 않습니다

## 마무리

사용자 가이드(`/guide`)의 성장형 설명을 7단계와 04 검토 및 개선(동료 점검 짝 배정 포함) 기준으로 갱신합니다.
