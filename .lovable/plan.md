# 도전형 활동기록 2차 — 과정기록 · 개발기록 · 교육적 점검 · 개인 후기

1차(팀원 관리 + 최종 결과물 + 반복행 5종 + 자동 저장)는 이미 동작 중입니다. 2차에서는 활동기록 편집기에 네 가지 영역을 추가합니다. 기존 저장·충돌 방지·권한 방식은 그대로 재사용합니다.

## 추가되는 4개 영역

1. **문제 정의 과정 기록** — 팀이 아이디어를 좁혀간 과정을 여러 줄로 기록
   - 열: 단계/날짜 · 우리가 나눈 이야기 · 그래서 정한 것
2. **개발 과정 자유기록** — 개발하며 겪은 일을 자유롭게 누적
   - 열: 날짜 · 무슨 일이 있었나 · 어떻게 해결했나
3. **교육적 점검 8항목** — 고정된 8개 질문에 `잘함 / 보통 / 아직`을 고르고 한 줄 메모
4. **개인 후기와 약속** — 팀원 각자 1개씩, 본인만 작성·수정

### 점검 8항목(초안 — 원하시면 문구 조정 가능)

1. 우리가 풀려는 문제를 스스로 설명할 수 있다
2. 사용자를 구체적으로 정했다
3. 아이디어를 여러 개 내보고 비교했다
4. 만들다 막혔을 때 스스로 방법을 찾아봤다
5. AI에게 물을 때 무엇을 원하는지 분명히 말했다
6. AI가 준 결과를 그대로 쓰지 않고 확인했다
7. 팀원과 역할을 나누고 서로 도왔다
8. 다른 사람의 자료를 쓸 때 출처를 밝혔다

## 화면

활동기록 상세에 아래 순서로 카드가 붙습니다(기존 카드 아래).

```text
[팀원] [최종 결과물] [핵심기능/사용흐름/한계/계획/제작자]   ← 1차 완료
[문제 정의 과정] [개발 과정 기록]                          ← 2차
[교육적 점검 8항목] [개인 후기와 약속]                      ← 2차
```

- 과정기록·개발기록: 1차 반복행과 완전히 같은 UI(행 추가/삭제, 행 단위 저장, "다른 팀원이 먼저 수정했어요" 안내).
- 점검 8항목: 8개 행이 고정으로 보이고, 라디오 3택 + 메모 한 줄. 처음 열면 빈 상태로 보이고 고를 때 저장됩니다.
- 개인 후기: 내 후기 칸 1개 + 팀원들의 후기 읽기 목록. 본인 닉네임 비밀번호로만 저장·수정하고, 남의 후기는 수정 버튼이 나오지 않습니다. 관리자는 삭제만 가능합니다.

## 데이터

- 과정기록·개발기록·점검은 **기존 `record_rows` 테이블을 그대로 재사용**합니다. `kind` 값에 `process`, `devlog`, `check` 세 가지를 추가하도록 검증 트리거(`validate_record_row_kind`)만 갱신합니다. 새 테이블 없음 = 정책·권한 추가 부담 없음.
- 개인 후기는 인원별 1건 제한이 필요하므로 새 테이블 `record_reflections`를 만듭니다.
  - `post_id, username, username_key, content, promise, updated_by, created_at, updated_at`
  - `unique (post_id, username_key)`
  - RLS 활성화 + 공개 읽기 정책 없음(모든 접근은 서버 함수 경유), `GRANT ALL ... TO service_role`만 부여 — 기존 활동기록 테이블과 동일한 보안 모델.

## 서버

`src/lib/record.functions.ts`에 최소한만 추가합니다.

- `saveRecordRow` / `deleteRecordRow`의 `kind` enum에 `process`, `devlog`, `check` 추가 (신규 함수 없음).
- `getRecord`는 이미 `record_rows` 전체를 읽으므로 그대로 두고, 후기 목록만 조회에 추가.
- 신규: `saveRecordReflection`, `deleteRecordReflection` — 팀원 여부 확인 후 **본인 `username_key`의 행만** 쓰기 허용, 관리자 비밀번호면 삭제 허용.

## 부작용 점검

- 새 요청 경로는 후기 저장뿐이고 나머지는 기존 행 저장 함수를 공유하므로 서버 호출량 증가는 미미합니다. 점검 8항목은 라디오 클릭 시 1회 저장(디바운스 없이 즉시 1건), 메모는 기존과 같은 1초 지연 저장.
- `record_rows`에 `kind`만 늘어나므로 1차 화면은 각 섹션이 `kind`로 필터링하고 있어 영향 없음.
- 활동기록 외 게시판·검색·읽음 처리 로직은 건드리지 않습니다.

## 마무리

- 사용자 가이드(`/guide`) 활동기록 섹션에 2차 4개 영역 사용법과 "후기는 본인만 수정" 규칙을 추가합니다.
