# 결선 투표 종료 후 최종 명단(1차 확정 10팀 + 결선 통과 2팀) 표시

## 문제

36개 중 12개를 뽑는 투표에서 1차에 10팀이 확정되고, 4표 동점 6팀 중 2팀을 결선으로 가렸습니다. 그런데 결선 화면에는 결선 후보 6팀만 나오고 1차에서 확정된 10팀이 목록에서 사라집니다.

확인된 원인:
- 결선 라운드(round > 1)에서는 목록을 결선 후보로만 필터합니다 — `src/components/VoteSection.tsx:151-154`의 `visible = posts.filter(p => runoffIds.has(p.id))`. 투표 중에는 맞지만, **종료된 뒤 결과 화면에서도 같은 필터가 걸려** 확정 10팀이 빠집니다.
- 선발 판정도 결선 후보 안에서만 계산됩니다(`VoteSection.tsx:165-201`), 그래서 "2팀만 선발"로 보입니다.
- 서버는 데이터를 잃지 않았습니다: 확정 명단은 `vote_locked_ids`에 그대로 있고(`platform.functions.ts:4565-4583, 4627-4628`), 1차 표도 `votes` 테이블에 `round=1`로 남아 있습니다. 다만 `getVoteResults`가 **현재 라운드 집계만** 반환합니다(`platform.functions.ts:4504-4509`).

즉 데이터 손실은 없고 표시 로직만 고치면 됩니다.

## 수정 내용

1. 결선이 **종료된 상태**에서는 목록을 두 묶음으로 보여줍니다.
   - 위쪽: 1차에서 확정된 팀(확정 배지 + 1차 득표수)
   - 아래쪽: 결선 후보들(결선 득표수 순, 통과한 팀에 선발 배지)
   - 최종 선발 = 확정 팀 + 결선 통과 팀 → 12팀이 한 화면에 모두 표시됩니다.
2. 결선이 **진행 중일 때**는 지금처럼 결선 후보만 보여 줍니다(투표 대상 혼동 방지). 안내 문구는 유지.
3. 상단 안내에 "확정 N팀 + 이번 결선 M자리 = 총 12팀" 요약을 표시합니다.
4. 확정 팀의 득표수는 그 팀이 확정된 라운드의 표를 그대로 보여 줍니다(1차 4표 초과분 등 원래 수치).

## 기술 세부

서버 `src/lib/platform.functions.ts`
- `getVoteResults`: 종료 상태일 때 `votes`를 라운드 필터 없이 한 번 읽어 `counts`(현재 라운드)와 `roundCounts: Record<number, Record<postId, number>>`를 함께 반환. 쿼리 수는 그대로 1회이므로 서버 부담 증가 없음.
- `VoteResultsDTO`에 `roundCounts` 추가(기존 필드 유지, 하위 호환).

프론트 `src/components/VoteSection.tsx`
- `visible`: `isRunoff && status === "closed"`이면 `[...확정팀, ...결선후보]`로 구성, 그 외는 현행 유지.
- 정렬: 확정 팀(자기 라운드 득표수 내림차순) → 결선 후보(이번 라운드 득표수 내림차순).
- `winnerInfo.winners`에 `lockedIds`를 합산해 선발 배지가 확정 팀에도 붙게 함. 동점 판정(`tied`)은 지금처럼 **결선 후보 집합 안에서만** 계산해 추가 결선 로직에 영향 없음.
- 카드 득표수 표기: 확정 팀은 `roundCounts[확정 라운드]`, 결선 후보는 현재 `counts` 사용. 확정 팀에는 "1차 확정" 배지.
- 순위(`rankMap`)는 결선 후보 목록 기준을 유지하고, 확정 팀에는 순위 대신 확정 배지만 표시(라운드가 달라 표 수 직접 비교가 성립하지 않기 때문).

가이드 `src/routes/_main.guide.tsx`
- 투표 게시판 섹션에 "결선 종료 후에는 1차 확정 팀과 결선 통과 팀이 함께 최종 명단으로 표시된다" 문구 추가.

## 부작용 검토

- DB 변경 없음, 마이그레이션 없음, 기존 표 데이터 그대로 사용.
- 추가 쿼리 없음(라운드 필터만 제거하고 클라이언트에서 그룹화).
- 1라운드만 진행한 게시판은 `isRunoff`가 false라 동작이 완전히 동일합니다.
- 작성자 공개 시점(`revealed`) 규칙은 변경하지 않습니다.
