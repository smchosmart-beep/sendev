# 나눔(온라인 갤러리 워크) 탭 추가

## 나눔 탭은 왜 만들어졌나

HTML 원본의 나눔은 연수 마지막 시간의 **발표 대체 활동**입니다. 앞에 나와서 설명하는 대신, 참가자가 자기 자리에서 동료의 기록(01~05)과 배포 주소를 직접 열어 써 보고 관찰을 남깁니다. 설계 의도는 세 가지입니다.

1. **설명 없이 써 보게 한다** — "설명해 줄 사람이 없습니다. 링크만 열어 보는 그 상황이 곧 가장 정직한 테스트입니다."
2. **강사 평가 없이 동료 평가만으로 발표자를 정한다** — 모둠(6명) 안에서 서로 3항목을 1~4점으로 매기고, 모둠 1위가 나옵니다.
3. **네 가지 학교 문제를 고르게 무대에 올린다** — 모둠 1위 15명 중 문제 영역별 상대점수 1위 1명씩, 총 4명이 전체 발표를 합니다.

즉 04(동료 점검, 짝 2명 · 개인 개선용)와 목적이 다릅니다. 04는 고치기 위한 관찰, 나눔은 **모둠 단위 상호 열람 + 점수 + 대표 선발**입니다. 그래서 04 안에 넣지 않고 게시판 단위 화면으로 만드는 것이 맞습니다.

## SenDev에 이식하는 방법

성장형 게시판 안에 **나눔 탭**을 하나 둡니다: `/board/{슬러그}/gallery`. 게시판(=기수) 하나가 곧 하나의 나눔 행사가 되고, 모둠·평가·집계가 게시판별로 완전히 분리됩니다. 기존 글 목록 화면 위쪽에 `기록 목록 · 나눔` 전환을 두어 들어갑니다(성장형 게시판에서만 표시).

로그인은 기존 닉네임 방식을 그대로 씁니다. 나눔에 들어가려면 마이페이지처럼 닉네임·비밀번호로 본인 확인을 하고, 그 닉네임으로 쓴 성장형 기록이 곧 "나의 기록"이 됩니다. 기록이 없는 사람은 열람만 가능합니다.

평가는 산출물 게시판의 기존 평가 기능을 쓰지 않고 **성장형 전용으로 새로 만듭니다**(원본대로 3항목 1~4점 고정).

## 화면 구성 (원본 그대로)

상단: `온라인 갤러리 워크` 제목, 참가 인원·모둠 수, `자리 이동 없음 · 내 모둠을 한 사람당 3분씩` 안내, 접었다 펴는 **전체 편성표**(모둠별 이름·학교·프로젝트·한 줄 소개·배포 주소).

그 아래 탭 3개:

**01 갤러리 워크**
- 왼쪽: 내 모둠 사람 목록(나의 기록은 `평가 제외` 표시, 끝낸 사람은 `✓ 둘러봄`), 상단에 `n / 5명 둘러봄`
- 오른쪽: 고른 사람의 기록을 원본 순서대로 — `01·02 프로젝트와 문제`(한 줄 소개, 해결하려는 문제, 문제를 발견한 경험) → `03 결과물`(핵심 기능 3개, 사용 흐름 3단계, **열어서 직접 써 보기** 버튼) → `04 검토 및 개선`(세 점검의 고친 것 · 어떻게 고쳤나 · 고치지 않기로 한 것) → `05 성찰과 성장`(새롭게 할 수 있게 된 것, 다음에 보완하고 싶은 것)
- 맨 아래 평가 카드: `배포 주소를 아직 안 열어 봤어요` 체크(체크 시 동작의 정확성은 집계 제외), **문제의 적절성 / 기대 효과 / 동작의 정확성** 각 1~4점, `내가 가져갈 한 줄`(40자, 선택), `평가 제출 · 둘러봄 기록`

**02 우리 모둠 결과**
- 12점 만점 순위표(세 항목 평균 합), 1위에 `모둠 1위` 표시, 내 카드에 `· 나`
- `배포 주소를 열지 않은 사람의 동작 정확성은 해당 항목 평균에서 제외` 안내
- `내가 받은 "내가 가져갈 한 줄"` 중 **2개 선택** → 07 성장 사례집에 익명 인용으로 자동 반영

**03 전체 발표 4인**
- 관리자가 `집계하기` → 모둠 1위들을 `본인 점수 ÷ 모둠 평균`으로 비교해 문제 영역별 1명, 총 4명 확정
- 발표자 카드: 발표 순서, 이름·소속·영역, 프로젝트, 한 줄 소개, 배포 주소 열기, **하트 보내기**(누적 수), `내 화면 공유 준비` 안내, `코멘트 한 줄`(80자) 남기기 — 코멘트는 발표자에게 실제로 보입니다
- 집계 전에는 `집계하기를 누르면 문제 영역별 상대점수 1위가 표시됩니다.`

## 관리자 (활동기록 현황 안에 나눔 관리)

- **자동 편성 버튼**: 해당 게시판의 성장형 기록 작성자를 문제 영역 기준으로 6명 내외 모둠으로 자동 배분. 다시 누르면 재편성, 개별 이동도 가능
- 나눔 열기/닫기(평가 제출 가능 시점), 진행 현황(모둠별 제출 수), `집계하기`(전체 발표 4인 확정) 및 되돌리기
- 엑셀 내려받기에 모둠·받은 점수·둘러본 수 열 추가

## 기술 메모

- 마이그레이션 1건 (성장형 전용, 기존 `reviews`/`review_criteria`는 건드리지 않음)
  - `record_growth_group`: `id`, `category_id`(→categories), `number`, `area`, `created_at/updated_at` — 모둠
  - `record_growth_group_member`: `id`, `group_id`, `post_id`(→posts, unique), `created_at` — 편성
  - `record_growth_evaluation`: `id`, `post_id`(평가 대상), `from_post_id`(평가자), `problem/effect/accuracy smallint`, `not_visited boolean`, `takeaway text`, `submitted boolean`, unique(post_id, from_post_id) — 동료 평가
  - `record_growth_quote_pick`: `post_id`, `evaluation_id` — 사례집에 쓸 인용 2개
  - `record_growth_stage`: `id`, `category_id`, `post_id`, `order_no`, `hearts int`, `aggregated_at` — 전체 발표 4인
  - `record_growth_stage_comment`: `id`, `stage_id`, `author`, `content(80)`, `created_at`
  - `record_growth_heart`: `id`, `stage_id`, `voter_key`, unique(stage_id, voter_key) — 하트 1인 1회
  - 다른 `record_*` 테이블과 동일한 보안 모델: RLS on, `service_role`만 GRANT, 접근은 서버 함수 경유
  - `categories`에 `gallery_open boolean default false` 추가(나눔 열기/닫기)
- 신규 `src/lib/record-gallery.functions.ts`: `getGalleryOverview`(편성표·내 모둠·내 기록), `getGalleryRecord`(대상 1명의 01~05 요약), `submitGalleryEvaluation`, `getGroupResult`, `pickQuotes`, `assignGroups`(관리자), `aggregateStage`(관리자), `sendHeart`, `addStageComment`. 인증은 기존 성장형과 동일한 닉네임 비밀번호/관리자 비밀번호 검증을 재사용하고, 평가자는 반드시 **같은 모둠**이며 자기 자신 평가는 서버에서 차단합니다.
- 신규 라우트 `src/routes/_main.board.$slug.gallery.tsx` + 컴포넌트 `src/components/gallery/*`(`GalleryWalkPanel`, `GroupResultPanel`, `StagePanel`). 탭은 기존 shadcn `Tabs` 사용, 카드/버튼 스타일은 기존 활동기록 화면과 동일.
- 점수 집계는 서버에서 계산해 내려보냅니다(항목 평균 합계 12점, `not_visited` 평가자는 동작의 정확성 평균에서 제외). 클라이언트는 표시만 합니다.
- `GrowthCasebookDocument.tsx`: 선택한 인용 2줄을 익명으로 싣는 블록 추가.
- 도전형 기록·투표·산출물 평가 기능과 `/guide`는 건드리지 않습니다.

## 사전 점검에서 반영한 안전장치

코드·DB를 직접 확인해 아래 위험을 계획에 미리 넣었습니다.

- **남의 기록이 공개로 새는 문제** — 나눔 라우트는 로그인 없이 열리는 공개 화면이라, 서버 함수를 그냥 두면 누구나 참가자 기록·배포 주소를 가져갈 수 있습니다. 편성표를 포함한 모든 나눔 조회·저장 함수는 기존 `ensureNickname`(닉네임+비밀번호) 또는 관리자 비밀번호를 통과해야 하고, 기록 상세는 **같은 게시판 참가자**에게만 내려보냅니다. (`record.server.ts:33,57`의 기존 검증 재사용)
- **도전형 글이 섞여 들어가는 문제** — 후보를 `posts.type='record'`와 카테고리로만 고르면 도전형 글도 포함될 수 있습니다. 편성·집계 모두 `categories.record_kind='growth'`를 함께 확인합니다. (기존 `getGrowthPeerAssignments`도 같은 방식으로 정리)
- **재편성 시 평가 유실** — 자동 편성을 다시 누르면 모둠만 바뀌고 이미 제출된 평가는 지우지 않습니다. 모둠이 바뀐 사람의 평가는 집계에서만 빠지며, 재편성 전에 "제출된 평가 n건이 있습니다" 경고를 띄웁니다. 파괴적 SQL(DROP/DELETE)은 쓰지 않습니다.
- **나눔이 계속 닫혀 보이는 문제** — `gallery_open`을 추가할 때 `platform.functions.ts:317`의 카테고리 조회 문자열과 DTO·수정 스키마(477·517·551·600)에 함께 넣습니다. 빠뜨리면 항상 닫힘으로 동작합니다.
- **하트·코멘트 남용** — 하트는 `unique(stage_id, voter_key)`로 1인 1회, 코멘트는 80자 제한과 닉네임 인증을 서버에서 강제합니다.
- **요청량** — 모둠 기록은 `in` 한 번으로 모아 오고(N+1 없음), 폴링은 두지 않습니다. 평가 저장은 제출 버튼 1회, 결과·집계는 열 때 1회 조회입니다.
- **집계 권한** — `집계하기`와 자동 편성은 관리자 비밀번호 검증(`isAdminPassword`)을 통과해야만 실행됩니다.
- **인용 2개 제한**과 자기 자신 평가 차단, 1~4점 범위 검증은 화면이 아니라 서버에서 확인합니다.
- 새 테이블은 기존 `record_*`와 동일하게 RLS 켜고 `service_role`만 GRANT합니다.
