# 도전형 활동기록 — 4단계 입력 구조 전면 개편

첨부한 HTML의 입력 구조를 그대로 반영하고, 활동기록 편집기를 **상단 스텝바 + 한 단계씩 입력**하는 방식으로 바꿉니다. 기존 데이터는 보존하지 않으며(초기화), 디자인은 지금의 sendev 톤(둥근 카드, `rounded-2xl`, 시맨틱 토큰, 부드러운 그림자)을 그대로 유지합니다.

## 화면 흐름

```text
[0 팀 공통정보]  [1 문제 정의]  [2 최종 결과물]  [3 개발·점검]  [4 개인 후기]
  └ 상단 스텝바(진행률·완료 표시) / 한 번에 한 단계만 노출 / 이전·다음 버튼
```

- 스텝바: 번호 원 + 단계명, 완료한 단계는 체크 표시, 클릭으로 바로 이동.
- 모바일에서는 스텝바가 가로 스크롤 없이 축약(번호 + 현재 단계명)되고, 하단에 이전/다음 버튼 고정.
- 저장은 지금처럼 자동(1초 지연) + 행 단위 즉시 저장. 단계 이동 시 대기 중 변경분을 먼저 저장.

## 각 단계에 들어가는 항목

**0. 팀 공통정보 (팀당 1건)**
팀명(글 제목), 프로젝트명, 문제영역·주 사용자·결과물 유형(선택형 + 직접 입력), 태그 최대 3개, 팀원과 역할 표(이름/소속/역할), 공개 동의 체크.

**1. 문제 정의 과정 (여러 건 누적)**
기록 종류(22일 팀빌딩·문제 정의 회의 / 인터뷰 기록 / 인터뷰 후 문제 구체화 회의 / 그 밖의 메모), 제목, 내용, 관련 링크, 관련 파일, 작성자, 작성 시각 자동 기록. 목록은 한 줄 카드로 쌓이고 클릭하면 펼쳐집니다. 종류 필터 + 최근순 정렬.

**2. 최종 결과물 (팀당 1건)**
- 소개: 프로젝트명, 배포 상태(Live/Beta/Demo), 사용 환경, 한 줄 설명, 최종적으로 해결하려는 문제, 해결 방식
- 링크: 배포 URL, GitHub, 시연 영상, 대표 화면
- 핵심 기능(행 추가): 기능명 / 한 줄 설명
- 사용 흐름(행 추가): 단계별 하는 일 + 사용 조건
- 기술 스택: 화면 / 처리·서버 / AI·외부 API / 저장 / 배포
- 디렉터리·설치·실행·환경변수 이름
- 현재 한계, 다음 계획

**3. 개발·교육적 점검 (8개 블록)**
- 자유 개발 기록(여러 건 누적: 작성자·제목·메모·링크·파일)
- 구현하며 바꾼 중요한 판단(행): 처음 결정 / 바꾼 결정 / 이유 / 결과
- 막혔던 순간(행): 무엇이 막혔나 / 어떻게 풀었나 / 무엇을 배웠나
- 교사와 학생의 자리(고정 4문항): 각 문항마다 `해당함 — 설계 내용` 또는 `해당 없음 — 이유`
- AI 활용과 사람의 확인(행): 활용 구분(서비스 기능/개발 과정) / 사용 도구 / AI에 맡긴 일 / 사람이 확인한 것
- AI의 실수를 잡은 사례(행): 잘못된 결과 / 발견 방법 / 수정 방법 / 재확인 결과
- 입력·전송·저장 정보(행): 정보 이름 / 입력 주체 / 외부 전송 / 저장 위치·기간 / 열람 범위 / 삭제 방법 + 개인정보 처리 여부
- 위험·대응·검증: 예상 위험 / 줄인 방법 / 멈춰야 하는 조건 / 테스트 범위
각 블록은 스텝 안에서 `미작성 / 작성됨` 배지로 상태를 보여 줍니다.

**4. 개인 후기·소회 (팀원별 1건)**
작성자 선택, 소속·역할, 3개 질문(펜 대신 키보드를 잡게 된 순간 / 만들고 싶었던 교실의 변화 / 교사 개발자의 약속), 약속 항목 7개 중 최대 2개 선택 + 반영 방법, 학교 확산 계획. 본인만 작성·수정, 관리자는 삭제만 가능(현행 규칙 유지).

## README 출력

`src/lib/record-readme.ts`를 HTML의 9블록 출력안에 맞춰 다시 작성합니다: 프로젝트명·한 줄 설명 → 링크/대표 화면 → 해결하려는 문제 → 주요 기능 → 사용 방법·조건 → 기술 구성과 실행 → 현재 상태·한계·다음 계획 → 교육 현장 사용 시 주의사항 → 제작자와 라이선스. 관리자 ZIP/엑셀 내려받기는 새 필드 기준으로 갱신합니다.

## 기술 메모

- 마이그레이션 1건:
  - `record_final`에 신규 컬럼 추가(프로젝트명, 문제영역, 주사용자, 결과물유형, 태그, 배포상태, 사용환경, 시연영상, 사용조건, 기술스택 5칸, 디렉터리/설치/실행, 한계, 다음계획, 개인정보 처리 여부, 위험·대응·검증 4칸, 공개동의).
  - `record_rows`에 `col4`~`col6`(text), `subtype`(text), `author`(text) 추가. 새 `kind` 값: `process`, `devlog`, `feature`, `flow`, `maker`, `decision`, `stuck`, `stance`, `ai_use`, `ai_error`, `privacy`. DB 검증 트리거 `validate_record_row_kind`, `RECORD_ROW_KINDS`, zod enum 4지점을 함께 갱신.
  - `record_members`에 `affiliation`, `role` 추가.
  - `record_reflections`에 `affiliation`, `role`, `q1`, `q2`, `promises`(text[]), `promise_detail`, `spread_plan` 추가.
  - 기존 `record_rows` / `record_final` / `record_reflections` 데이터는 삭제(보존 불필요).
  - 모든 신규 컬럼은 기존 보안 모델 유지(RLS on, `service_role`만 GRANT).
- 서버 함수는 신규 없이 기존 `saveRecordFinal` / `saveRecordRow` / `saveRecordReflection`의 스키마만 확장합니다. 호출 횟수·데이터량이 거의 그대로라 서버 부하 변화는 없습니다.
- `src/components/RecordEditor.tsx`는 스텝 셸(`RecordEditor`) + 단계별 컴포넌트 5개로 분리하고, 반복행 UI는 4~6열을 받을 수 있는 공용 `RowSection`으로 일반화합니다. 파일 분할 위치: `src/components/record/`.
- 현재 단계는 `localStorage`에 글 단위로 기억해 다시 들어와도 이어서 작성합니다.

## 마무리

- 사용자 가이드(`/guide`) 활동기록 섹션을 새 4단계 구조와 각 단계 작성 요령으로 갱신합니다.
- 관리자 활동기록 현황(`/admin/records`)의 진행률 계산과 엑셀 열을 새 구조에 맞춥니다.
