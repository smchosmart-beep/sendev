# 02 문제 정의 과정 — 탭 5개 구조로 개편

## 새 탭 구성

| 새 탭 | 입력 양식 |
|---|---|
| 1. 페르소나 | 페르소나 템플릿 안내(복사 버튼) + 페르소나 이미지 첨부(드롭존, 크게 미리보기) |
| 2. 고객 여정 맵 | 고객 여정 맵 템플릿 안내(복사 버튼) + 여정 맵 이미지 첨부 |
| 3. 인터뷰 기록 | 현행 유지 (인터뷰 질문 · 대상 · 내용) — 이미 있는 '기록한 사람' 칸을 그대로 쓰며 팀원별 여러 건 추가 가능 |
| 4. 회고&문제정의 | 현행 [인터뷰 후 문제 구체화 회의] 양식(가설 일치 / 불일치 / 새로 알게 된 내용) + 관련 링크 · 관련 파일 칸 추가 |
| 5. 종이 프로토타입 영상 콘티 | 유튜브 링크(재생 버튼) + 콘티 설명(여러 줄) |

[그 밖의 문제 정의 메모] 탭은 없어집니다.

## 인터뷰 기록만 팀원별 다중 작성

- [1·2·5]와 [4. 회고&문제정의]는 팀당 1건 기준(빈 양식 1벌만 표시, 추가 버튼 없음)으로 유지합니다.
- [3. 인터뷰 기록]만 [+ 인터뷰 기록 추가] 버튼을 노출해 팀원 누구나 자기 인터뷰를 여러 건 추가할 수 있게 합니다.
  - '기록한 사람' 칸은 지금도 모든 02단계 행에 있고 로그인 닉네임이 기본값으로 채워집니다. 새로 만드는 게 아니라, 인터뷰 행에서 눈에 잘 띄도록 헤더 표기만 다듬습니다("인터뷰 1 · 작성자").
  - 행 목록은 작성순으로 정렬합니다.
  - README·사례집 출력에서도 인터뷰 기록은 여러 건이 순서대로 나열되며 작성자 이름이 함께 표기됩니다.
  - 진행도(작성 현황) 집계는 인터뷰 기록이 1건 이상 채워지면 완료로 봅니다.

## 오조작 방지 (검토에서 확인된 사항)

- 지금은 각 기록 행 안쪽에도 탭 버튼이 그려지고, 이미 선택된 버튼을 다시 누르면 그 행의 기록 종류가 비워져 어느 탭에서도 보이지 않게 됩니다. 탭이 5개가 되면 더 잘 발생하므로, 행 안쪽 탭 버튼은 제거하고 탭 선택은 섹션 상단(모바일 드롭다운 / PC 탭 버튼)에서만 하도록 정리합니다.

## 기존 데이터 자동 이관

현재 02단계 기록은 전체 2행([22일 팀빌딩] 1행, [그 밖의 메모] 1행)뿐이라 이관 범위가 매우 작고, 표 구조 변경 없이 **데이터만 갱신**합니다(스키마 마이그레이션 아님). 내용 손실은 없습니다.

- [22일 팀빌딩·문제 정의 회의] 행 1개 → 최대 3개 행으로 분리
  - 페르소나 이미지가 있으면 → [1. 페르소나] 행
  - 고객 여정 맵 이미지가 있으면 → [2. 고객 여정 맵] 행
  - 유튜브 링크가 있으면 → [5. 종이 프로토타입 영상 콘티] 행
- [인터뷰 기록] → [3. 인터뷰 기록] (내용 그대로)
- [인터뷰 후 문제 구체화 회의] → [4. 회고&문제정의] (내용 그대로)
- [그 밖의 문제 정의 메모] → [4. 회고&문제정의]로 이동. 기존 3칸(언제·어디서 / 나눈 이야기 / 정한 것) 텍스트는 라벨을 붙여 '새로 알게 된 내용' 칸 하나로 합치고, 관련 링크·관련 파일은 그대로 유지됩니다.
- 빈칸뿐인 행은 이관 시 생성하지 않습니다.

## 함께 반영할 것

- README 출력·사례집 PDF 출력에서 새 탭 이름과 순서(1→5)로 표시
- 모바일 드롭다운 / PC 탭 버튼 구조는 그대로 유지 (탭 5개로)
- 사용자 가이드(/guide) 02단계 설명을 새 탭 구조·양식·이관 내용에 맞게 갱신

## 기술 메모

- `src/lib/record-schema.ts`: `PROCESS_SUBTYPES`, `PROCESS_SUBTYPE_TEMPLATES`, `PROCESS_TEMPLATE_NOTICES`를 새 5탭 기준으로 재정의. 저장 열 인덱스는 기존과 동일하게 유지(페르소나=col5, 여정맵=col6, 링크=col4, 파일=col5 등 기존 매핑 보존)해 데이터 호환성 확보.
- `src/components/RecordEditor.tsx`: `defaultSubtype`을 첫 탭으로 변경. 추가 버튼 노출 조건을 "메모 탭 한정"에서 "인터뷰 기록 탭 한정(multi 탭)"으로 교체 — 스키마에 탭별 `multi: boolean` 플래그를 두고 그 값으로 판단. 가상(빈) 행 표시 로직은 5개 탭 모두에 적용(단일 탭은 1개만). 인터뷰 행의 작성자는 기존 `record_rows.author` 컬럼을 사용하며 로그인 닉네임을 기본값으로 채움.
- `src/lib/record-readme.ts`, `src/components/record/CasebookDocument.tsx`: 하드코딩된 탭 이름·정렬 기준 갱신.
- 마이그레이션은 `record_rows` 대상 INSERT/UPDATE 스크립트 1건(스키마 변경 없음).
