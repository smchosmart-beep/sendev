# 투표 제어에 관리자 비밀번호 확인 추가

투표 시작 / 종료 / 초기화 버튼을 누를 때, 그 자리에서 관리자 비밀번호를 입력해 통과해야만 실행되도록 바꿉니다.

## 현재 상태

- 서버 함수 `setVoteStatus` / `resetVotes`는 이미 서버에서 관리자 비밀번호를 검증합니다(틀리면 "권한이 없습니다."로 거부). 즉 실제 권한 우회는 불가능한 상태입니다.
- 다만 화면에서는 브라우저 세션에 저장된 값의 존재 여부만 보고 관리자 패널을 그리므로, 값이 잘못돼도 버튼이 보일 수 있습니다.

## 바뀌는 동작

- `투표 시작`, `투표 종료`, `초기화` 버튼을 누르면 **관리자 비밀번호 입력 창**이 먼저 뜹니다.
- 입력한 비밀번호로 서버 검증을 통과해야 해당 동작이 실행됩니다. 틀리면 "비밀번호가 올바르지 않습니다." 안내만 뜨고 상태는 그대로입니다.
- `투표 시작` 창에서는 기존처럼 1인당 최대 투표 수도 함께 입력합니다. 다이얼로그가 열릴 때 초기값은 현재 설정값으로 채웁니다.
- `초기화`는 기존 확인 창(되돌릴 수 없음)을 거친 뒤 비밀번호 입력을 요구합니다. `resetVotes` 성공 후 `setVoteStatus('idle')`을 순차 실행해 부분 실패(표만 지워지고 상태는 open 유지)를 방지합니다.
- 통과한 비밀번호는 해당 실행에만 사용하고, 그 창을 닫으면 입력값은 남기지 않습니다.

## 기술 메모

- `src/components/VoteSection.tsx`
  - `AdminVoteControls`에 관리자 비밀번호 확인용 다이얼로그(shadcn `Dialog` + `PasswordInput`) 추가.
  - 세 동작 모두 `sessionStorage` 값을 그대로 쓰지 않고, 다이얼로그에서 입력받은 비밀번호를 `setVoteStatus` / `resetVotes`의 `adminPassword`로 전달.
  - 1인당 최대 투표 수 입력을 시작 다이얼로그 안으로 이동. 패널에는 현재 설정값을 읽기 전용 텍스트로 표시하고, 시작 다이얼로그의 초기값은 현재 `maxChoices`로 채웁니다.
  - 오류 응답("권한이 없습니다.")은 다이얼로그 안에서 인라인 오류로 표시하고 창을 열어 둠.
  - 초기화 버튼은 `resetVotes` 성공 후 `setVoteStatus('idle')`을 순차 호출하며, 실패 시 상태를 변경하지 않습니다.
- 서버 함수는 변경 없음(이미 `requireAdmin` 검증 존재).
- 결과 조회에 쓰이는 `adminPassword`(투표자 명단 열람) 경로는 그대로 두어 기존 동작 유지.
- 비용/캐시: 추가 폴링이나 신규 쿼리 없음. 다이얼로그 확인은 기존 `setVoteStatus`/`resetVotes` 호출을 그대로 쓰므로 요청 수 변화 없음.
- 미확인: `useConfirm`과 새 다이얼로그를 동시에 열 때의 포커스 트랩 중첩 동작(초기화 흐름)은 구현 후 실제 화면에서 확인이 필요합니다.
- `src/routes/_main.guide.tsx`: 투표 게시판 안내에 "투표 시작·종료·초기화는 관리자 비밀번호 입력이 필요합니다" 문구 추가.
