# 사용자 프로필 관리 — 목록 탭 + 검색·필터·페이지네이션

사용자가 많아질 때를 대비해, 사용자 프로필 관리 화면을 **탭으로 분리**하고 사용자 목록에 **검색·필터·페이지네이션**을 추가합니다.

## 화면 구성 (탭 분리)
`src/routes/admin.profiles.tsx`의 `ProfilesAdmin`을 shadcn `Tabs`로 감쌉니다.

- **탭 1 · 사용자 목록**: 검색창 + 필터 + 정렬 + 페이지네이션이 적용된 사용자 목록(현재 목록 UI 재사용: 레벨/배지 칩/배지 삭제/배지 추가(+)/비밀번호 초기화/삭제).
- **탭 2 · 관리 설정**: 사용자·배지 추가 폼, 배지 아이콘 설정(`AwardIconPicker`), 배지 아이콘 규칙(`AwardIconRules`).

## 사용자 목록 탭 기능
데이터(`listUserProfiles`)는 지금처럼 한 번에 불러오고, 화면에서 거르고 나눕니다.

1. **검색**: 사용자명 입력 → 대소문자 무시 부분일치 필터.
2. **필터** (`Select` 드롭다운 2개):
   - 배지: 전체 / 배지 있음 / 배지 없음
   - 활동: 전체 / 활동 있음(레벨 보유) / 활동 없음
3. **정렬** (`Select`): 이름순 / 점수 높은순 / 점수 낮은순.
4. **페이지네이션**: 페이지당 20명, shadcn `Pagination`으로 이전/다음 및 페이지 번호 이동. 검색·필터·정렬이 바뀌면 1페이지로 초기화.
5. 결과 위에 "전체 N명 중 검색 결과 M명" 요약 표시. 결과 0이면 빈 상태 메시지.

## 기술 메모
- 필터/검색/정렬/페이지 상태는 `useState`로 컴포넌트 내부 관리(`useMemo`로 파생 목록 계산).
- 기존 mutation(배지 추가/삭제, 프로필 삭제, 비번 초기화)과 쿼리 무효화 로직은 그대로 사용.
- 현재 `listUserProfiles`는 한 번에 모든 프로필을 반환하므로 수백~천 명 규모까지 화면 단 처리로 충분합니다. 그 이상 대규모가 되면 서버측 페이지네이션으로 전환이 필요하며, 이는 별도 작업으로 남겨둡니다.
