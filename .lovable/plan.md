# 문제 정의 과정 기록에 관련 링크·관련 파일 추가

02 단계(문제 정의 과정)의 각 기록 카드에 **관련 링크**와 **관련 파일**을 붙일 수 있게 합니다. 기존 3개 칸(언제·어디서 / 무엇을 나눴나요? / 그래서 정한 것)과 기록 종류·기록한 사람은 그대로 둡니다.

## 화면

각 기록 카드 하단에 두 줄을 추가합니다.

```text
[언제·어디서] [무엇을 나눴나요?] [그래서 정한 것]
관련 링크  : (한 줄 입력, 예) https://docs.google.com/... )
관련 파일  : [파일 첨부] 버튼 + 첨부된 파일 칩(파일명 · 삭제)
[저장] [삭제]
```

- 관련 링크: 자유 입력 한 줄. 저장 시 `http`가 없으면 `https://`를 앞에 붙여 보정(기존 링크 보정 규칙과 동일).
- 관련 파일: 여러 개 첨부 가능(**최대 3개**, 개당 3MB 이하). 고르는 즉시 업로드되고 파일명 칩으로 표시되며, 클릭하면 원래 파일명으로 내려받습니다(기존 `downloadFile` 사용). 칩의 X로 목록에서 제거.
- 첨부/삭제 후에도 저장은 기존과 동일하게 카드의 [저장] 버튼으로 확정됩니다.
- 파일은 고르는 즉시 업로드되므로, 저장하지 않고 나가면 스토리지에 파일만 남습니다(기존 게시글 첨부와 동일한 동작). 용량 영향이 작아 별도 정리 로직은 두지 않습니다.

## 데이터

`record_rows`에 이미 있는 빈 열을 사용하므로 **마이그레이션 없음**.

- `col4` = 관련 링크(문자열)
- `col5` = 첨부 파일 목록 JSON 문자열 `[{"name":"회의록.hwp","url":"<signed url>"}]`

`saveRecordRow`는 이미 `col4`~`col6`을 최대 3000자로 받아 저장하므로 서버 함수 변경은 없습니다. 다만 서명 URL은 10년 TTL 토큰이라 개당 300~400자로 길어, 첨부 상한을 **3개**로 두고 저장 직전 JSON 길이가 **2900자를 넘으면** "첨부가 너무 많아요"로 막아 3000자 초과 저장 실패를 방지합니다.

## 기술 메모

- `src/lib/record-schema.ts`의 `ROW_SECTION_DEFS.process`에 `cols`/`placeholders`를 늘리지 않고, 새 옵션 `linkCol?: number`(=3)와 `fileCol?: number`(=4)를 추가해 `RowSection`이 해당 열을 일반 텍스트 칸 대신 링크 입력·파일 첨부 UI로 렌더링하게 합니다. 다른 섹션 정의는 옵션이 없어 영향 없음.
- 파일 업로드는 `PostEditor`와 같은 방식: `post-files` 버킷에 `crypto.randomUUID()+확장자`로 업로드 후 `createSignedUrl(..., { download: 원래파일명 })`. 이 로직을 `src/lib/file-upload.ts`로 뽑아 `RecordEditor`에서 재사용합니다(PostEditor는 그대로 두어 회귀 위험 제거).
- 파일 칩 아이콘은 기존 `getFileIcon`, 내려받기는 기존 `downloadFile` 재사용.
- 출력 보기(`src/lib/record-readme.ts`)는 `col5`의 JSON을 그대로 찍지 않고 파싱해 `[파일명](url)` 마크다운 링크 목록으로 변환합니다. 파싱 실패 시 해당 칸은 생략(원본 JSON 노출 금지). `col4` 링크도 마크다운 링크로 표기합니다.
- 관리자 현황(`/admin/records`)의 진행률은 행 개수 기준이라 변경 없음.

## 부작용 점검

- 새 서버 함수·새 쿼리·마이그레이션 없음. 저장 호출 횟수도 기존과 동일(카드 단위 1회). 업로드만 사용자가 파일을 고를 때 발생.
- `col4`/`col5`는 `process` 종류에서 지금까지 항상 빈 값이라 기존 데이터와 충돌 없음.
- 다른 단계·다른 섹션·게시판/댓글 첨부 기능은 건드리지 않습니다.
