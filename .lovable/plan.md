# 관리자 비밀번호로 활동기록 수정이 안 되는 문제

## 무엇이 일어나고 있나

활동기록 글 상단 오른쪽의 **[수정]** 버튼은 글 자체(제목·작성자·GitHub 링크 등)를 고치는 버튼입니다. 그래서 여기에 관리자 비밀번호를 넣으면 스크린샷처럼 **"산출물 수정"** 창(제목/작성자/링크)이 뜹니다. 활동기록 내용(사진 회전 포함)을 고치는 잠금 해제는 그 아래 **[관리자로 수정하기]** 버튼 쪽에 따로 있어, 두 개가 헷갈리는 상태입니다.

## 고칠 내용

1. **버튼 이름 구분**  
   활동기록 글에서는 상단 [수정] 버튼을 **[글 정보 수정]**으로 표시하고, 비밀번호 창 설명에 "활동기록 내용은 아래 [관리자로 수정하기]에서 수정합니다"라는 안내 한 줄을 넣습니다. (다른 게시판 글은 그대로 [수정])

2. **관리자 비밀번호를 한 번만 입력하면 되게**  
   상단 비밀번호 창에 넣은 값이 관리자 비밀번호로 확인되면, 그 값을 관리자 세션에 저장해 **활동기록 편집 잠금도 함께 풀립니다**. 즉 [글 정보 수정]으로 들어갔다 나와도 아래 활동기록이 이미 "관리자 권한으로 편집 중" 상태가 됩니다.

3. **[관리자로 수정하기] 버튼을 눈에 띄게**  
   지금은 회색 안내 박스 안에 작게 있어 잘 안 보입니다. 활동기록 단계 버튼 바로 아래에 강조된 형태(테두리·아이콘 유지, 문구 "관리자 비밀번호로 활동기록 수정")로 배치합니다.

## 기술 상세

- `src/routes/_main.board.$slug.$postNo.tsx`
  - `editGateMutation.onSuccess`에서 입력값을 `isRecordAdmin`(`src/lib/record.functions.ts`)으로 한 번 검증하고, 관리자면 `setAdminPassword(editGatePw)` 호출.
  - `post.type === "record"`일 때 헤더 버튼 라벨과 게이트 다이얼로그 안내 문구 분기.
- `src/lib/admin-auth.ts`
  - `setAdminPassword`에서 `window.dispatchEvent(new Event("admin-password-changed"))`를 함께 발생시킵니다(세션 저장 방식·서버 검증은 그대로).
- `src/components/RecordEditor.tsx`
  - `useEffect`로 위 이벤트를 구독해 `adminPw` 상태를 갱신 → `canEdit`/`isAdminEditing`이 새로고침 없이 즉시 반영.
  - `관리자로 수정하기` 블록 문구·배치만 조정(권한 로직 변경 없음).
- 서버 로직·DB 변경 없음. 권한 판정은 기존대로 서버(`requireTeamMember`의 관리자 분기)에서만 이뤄집니다.

## 가이드 갱신

`src/routes/_main.guide.tsx` 활동기록 항목에 "상단 [글 정보 수정]은 제목·작성자용, 활동기록 내용은 [관리자 비밀번호로 활동기록 수정]으로 연다"는 설명을 추가합니다.

## 검증

- 관리자 비밀번호로 상단 게이트 통과 → 창을 닫아도 활동기록이 편집 가능 상태인지 확인
- [관리자로 수정하기]로 바로 해제 → 사진 회전 후 저장 성공 확인
- 틀린 비밀번호 → 어느 쪽도 열리지 않음
- 팀원(일반 사용자) 흐름과 다른 게시판 글의 [수정] 동작에 변화 없음
