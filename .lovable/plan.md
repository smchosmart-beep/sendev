## 목표

3단계 위계 중 **중간 단위**(여러 게시판을 묶는 단위: [Lv1]입문형, 베타테스터 모집, 보도자료, 해커톤 사례집 등)를 가리킬 때 잘못 쓰인 "게시판"을 **"카테고리"**로 통일합니다.

- **유지(변경 안 함):** 실제 게시판 종류 명칭 — `공지사항`, `질문 게시판`, `일반게시판`, `산출물 게시판`, `링크 게시판`, "사용할 게시판 종류", placeholder 예시("예: 자유게시판")
- **변경:** 그 외 중간 단위/카테고리를 뜻하는 모든 "게시판" 텍스트

## 변경 대상 파일 및 문구

**src/routes/admin.tsx**
- `게시판(카테고리) 관리 …` → `카테고리 관리 …`
- 사이드바 라벨 `게시판 관리` → `카테고리 관리`

**src/routes/admin.notices.tsx**
- `게시판을 선택해 …` → `카테고리를 선택해 …`
- 라벨 `게시판 선택` → `카테고리 선택`
- 빈 상태 `게시판이 없어요.` / `먼저 '게시판 관리'에서 게시판을 …` → `카테고리가 없어요.` / `먼저 '카테고리 관리'에서 카테고리를 …`

**src/routes/admin.criteria.tsx**
- 라벨 `게시판 선택` → `카테고리 선택`

**src/routes/admin.categories.tsx** (중간 단위 관리 페이지)
- 오류 `게시판을 불러오지 못했어요` → `카테고리를 …`
- 토스트 `새 게시판이 추가/정보가 수정/삭제되었어요` → `카테고리 …`
- 제목 `새 게시판 추가`, `게시판 목록`, `게시판 수정` → `새 카테고리 추가` / `카테고리 목록` / `카테고리 수정`
- 검증 `게시판 이름을 입력해주세요` → `카테고리 이름을 …`
- 안내 `이 게시판이 상단 어느 탭에…`, `이 게시판에 표시할 섹션만…`, `게시판에 대한 간단한 설명`, `이 게시판에 산출물을 등록할 때…` → "이 카테고리…"
- 라벨 `게시판 이름` → `카테고리 이름`
- placeholder `비워두면 공개 게시판` / `비워두면 공개 게시판으로 변경` → `… 공개 카테고리`
- 빈 상태/삭제 다이얼로그 `해당하는 게시판이 없어요`, `… 게시판을 만들어보세요`, `게시판을 삭제할까요?`, `… 게시판이 삭제됩니다` → "카테고리"
- 유지: `사용할 게시판 종류`, placeholder `예: 자유게시판`

**src/routes/_main.board.index.tsx** (카테고리 목록 페이지)
- head title `게시판 — …` → `카테고리 — …`, description "게시판별로" → "카테고리별로"
- 오류/빈 상태 `게시판을 불러오지 못했어요`, `아직 등록된 게시판이 없어요`, `… 게시판을 추가해보세요` → "카테고리"

**src/routes/_main.board.$slug.tsx**
- 오류 `게시판을 불러오지 못했어요`, `게시판을 찾을 수 없어요`, `이 게시판은 비밀번호가 필요해요` → "카테고리"
- 뒤로가기 라벨 `게시판 목록` → `카테고리 목록`

**new-question / new-project / new-general / new-link / series.$series**
- `게시판을 찾을 수 없어요` → `카테고리를 찾을 수 없어요`
- 뒤로가기 `게시판으로` → `카테고리로`
- new-project `이 게시판은 GitHub 링크가 필수예요/입니다` → `이 카테고리는 …`
- new-link `게시판에서 하나의 카드로 묶여…` → `카테고리에서 …`

**src/routes/_main.board.$slug.$postNo.tsx**
- `이 게시판은 아직 평가 기준이…`, `이 기기는 이 게시판에서…`, `이 게시판의 첫 닉네임으로…`, `이 게시판의 모든 산출물 평가를…` → "이 카테고리"
- 뒤로가기 `게시판으로` → `카테고리로`
- (코드 주석의 "이 게시판" 표현도 일관성 위해 "이 카테고리"로 정리)

**src/lib/platform.functions.ts**
- 오류 메시지 `이 게시판은 GitHub 링크가 필수입니다.` → `이 카테고리는 GitHub 링크가 필수입니다.`

## 비고

- 순수 UI 텍스트(문구) 변경만 진행하며, DB 컬럼/필드명(`generalName` 등)이나 로직은 변경하지 않습니다.
- 작업 후 미리보기에서 관리자/일반 화면의 문구가 올바르게 바뀌었는지 확인하고, 변경 사항은 Publish 후 sendev.kr에도 반영됩니다.
