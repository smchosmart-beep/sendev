# 이미지 첨부 영역 드래그앤드롭 개선 계획

## 현재 상태

- `src/components/RecordEditor.tsx`의 `RowItem` 컴포넌트에서 이미지/파일 첨부는 "+ 이미지 첨부" outline 버튼을 클릭해 hidden `<input type="file">`을 여는 방식이다.
- 이미지 첨부 컬럼은 `RowTemplate.imageCols`에 지정된 열(예: 02 문제정의과정의 "페르소나 이미지", "고객 여정 맵 이미지")에만 적용된다.

## 목표

- 이미지 첨부 컬럼을 **드래그앤드롭 가능한 영역**으로 변경한다.
- 파일이 없을 때는 안내 영역을, 있을 때는 미리보기와 추가 영역을 함께 제공한다.
- 기존 제한(최대 3개, 개당 3MB, 업로드 중 로딩, 제거 버튼)과 UI 토큰은 그대로 유지한다.
- 사용자 가이드(`src/routes/_main.guide.tsx`)의 해당 안내 문구도 함께 갱신한다.

## 구현 내용

### 1. 드롭존 UI 추가

- `RowItem`의 이미지 첨부 컬럼 렌더링 부분을 변경한다.
- `fileCols` 중 `imageCols`에 포함된 열은 아래 형태로 렌더링:
  - **파일 없음**: 점선 테두리(dashed border) 영역에 "이미지를 여기에 끌어다 놓거나 클릭해서 첨부" 안내 + `ImagePlus` 아이콘.
  - **파일 있음**: 기존 이미지 미리보기를 그대로 보여주되, 마지막 항목 뒤에 (또는 상단/하단에) 추가용 드롭존 작은 영역 배치. 최대 3개에 도달하면 추가 영역 숨김.
- 드롭존은 클릭 시에도 기존 hidden input을 열도록 연결한다.

### 2. 드래그 이벤트 처리

- `dragenter`, `dragover`, `dragleave`, `drop` 이벤트를 등록한다.
- `dragover`에서 `e.preventDefault()`로 브라우저 기본 동작(파일 열기)을 막는다.
- 드롭 시 `e.dataTransfer.files`를 받아 첫 번째 이미지 파일을 업로드 로직에 전달한다.
- 드래그 중 상태에 따라 시각적 피드백(배경색/테두리 강조)을 준다.
- 업로드 중이거나 최대 개수에 도달한 경우 드롭을 무시하도록 처리한다.

### 3. 업로드 로직 재사용

- 기존 `handleFilePick`의 검증(개수, 용량, 직렬화 길이)과 `uploadAttachment` 호출을 별도 함수로 분리하거나, 드롭 경로에서도 동일한 로직을 타도록 한다.
- 업로드 성공/실패 토스트 메시지는 기존과 동일하게 유지한다.

### 4. 접근성 및 반응형

- 드롭존에 `role="button"`, `aria-label`, `tabIndex={0}`을 부여한다.
- Enter/Space 키로도 파일 선택 창을 열 수 있게 한다.
- 모바일에서 터치로도 클릭 선택이 가능하도록 유지한다.
- 이미지 미리보기는 기존처럼 `max-w-2xl`, `max-h-[28rem]`로 제한한다.

### 5. 가이드 문서 갱신

- `src/routes/_main.guide.tsx`의 활동기록 > 02 문제정의과정 > 이미지 첨부 안내 문구를 "드래그앤드롭 또는 클릭으로 이미지 첨부" 형태로 수정한다.

## 영향 범위

- `src/routes/_main.guide.tsx` (안내 문구)
