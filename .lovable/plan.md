# 해커톤 후기 담벼락 좌우 폭 불균형 수정

## 현상

노트북/일반 데스크톱 화면에서 본문(가운데) 기준으로 왼쪽 후기 담벼락과 오른쪽 후기 담벼락의 가로 폭이 달라 보이고, 오른쪽 카드가 화면 끝에서 잘려 보입니다.

## 원인 (코드 확인)

`src/components/HackathonReviews.tsx`의 `HackathonReviewSideColumns` 안 `wall()`은 좌우 패널을
`fixed ... w-[calc(50%-33rem)]` + `left-1` / `right-1`로 배치합니다.

- 폭은 `50% - 33rem`으로 계산하지만 본문은 `max-w-5xl`(64rem)이라 기준값(66rem)과 어긋납니다.
- 왼쪽은 `left-1`에서 폭만큼 오른쪽으로, 오른쪽은 `right-1`에서 폭만큼 왼쪽으로 자라기 때문에,
  세로 스크롤바 폭이나 기준값 오차가 한쪽(오른쪽)에만 잘림으로 나타납니다.

## 변경 계획

`wall()`의 위치 지정을 "폭 계산" 대신 "양쪽 끝 고정(inset)" 방식으로 바꿉니다.

- 왼쪽 패널: `left-1 right-[calc(50%+33rem)]`
- 오른쪽 패널: `right-1 left-[calc(50%+33rem)]`
- `w-[calc(50%-33rem)]` 제거

이렇게 하면 두 패널 모두 화면 중앙을 기준으로 동일한 거리에서 시작하고, 바깥쪽 여백도 동일하게
`1`(0.25rem)로 끝나므로 좌우 폭이 항상 대칭이 됩니다.

추가로:

- 내부 두 열(`marqueeColumn`)에 `min-w-0`을 적용해 카드가 컨테이너보다 넓어져 잘리는 일을 막습니다.
- 좁은 화면에서 패널 폭이 0 이하가 되지 않도록 기존처럼 `xl:block` 조건은 유지합니다(그 아래 폭에서는 기존 모바일 스트립 사용).

## 영향 범위

- `src/components/HackathonReviews.tsx` 한 파일의 CSS 클래스만 수정합니다.
- 데이터 조회, 후기 작성/수정 권한, 애니메이션 로직은 변경하지 않습니다.

## 검증

- 1920px, 1440px, 1280px 폭에서 좌우 담벼락 폭이 동일하고 오른쪽 카드가 잘리지 않는지 확인합니다.
- 본문(해커톤 목록)이 여전히 중앙 정렬되고 담벼락과 겹치지 않는지 확인합니다.
