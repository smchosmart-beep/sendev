## 목표

일반·질문·공지 게시판 글 본문(마크다운)에 캔바/유튜브/비메오 링크가 한 줄로 단독 입력되면, 그 자리에 바로 임베드 플레이어(iframe)로 표시합니다. 링크 게시판에서 이미 쓰는 `getEmbedUrl` 로직을 그대로 재사용합니다.

## 동작 방식

- 본문 안에서 링크가 **한 단락(줄)에 단독**으로 있을 때만 임베드로 변환합니다. (예: 캔바 view 링크, 유튜브 watch/shorts/youtu.be 링크)
- 문장 중간에 섞여 있는 링크는 지금처럼 클릭 가능한 일반 링크로 둡니다.
- 임베드는 16:9 반응형 영역(`aspect-video`)으로 렌더링하고, 임베드 아래에 "원본 링크 열기" 작은 링크를 함께 둡니다.
- 캔바/유튜브가 아닌 임베드 불가 링크는 변경 없이 일반 링크로 표시합니다.

## 변경 사항

대상 파일: `src/routes/_main.board.$slug.$postNo.tsx`

1. 본문을 렌더링하는 `<ReactMarkdown>`(204~220줄 부근)의 `components`에 커스텀 렌더러를 추가합니다.
   - `p` 컴포넌트: 단락의 자식이 "링크 하나뿐"인 경우 그 URL을 `getEmbedUrl`로 검사해, 임베드 가능하면 `<EmbeddedFrame>`(iframe + 원본 링크)로 대체합니다. 아니면 기존처럼 단락으로 렌더링합니다.
   - `a` 컴포넌트: 기존 동작(새 탭 열기) 유지.
2. 재사용 가능한 작은 `EmbeddedFrame` 컴포넌트를 같은 파일에 추가합니다. (기존 `LinkEmbedSection`의 iframe 마크업 재사용 — `allow`, `allowFullScreen`, 16:9 박스)
3. `getEmbedUrl`은 이미 import되어 있으므로 추가 import 없음.

> 참고: 본문은 이미 `remarkGfm` + `rehypeRaw`로 처리되며, "맨 URL"도 `remarkGfm`의 autolink로 `<a>`가 되므로 그냥 링크만 붙여 넣어도 임베드가 적용됩니다. 별도 입력 필드는 추가하지 않습니다.

## 검증

- 질문/일반/공지 글 본문에 유튜브 링크, 캔바 view 링크를 각각 한 줄로 넣고 미리보기에서 플레이어로 보이는지 확인.
- 문장 중간 링크는 일반 링크로 유지되는지 확인.
- 모바일(현재 뷰포트)·PC 양쪽에서 16:9 비율이 깨지지 않는지 확인.
