# 개인정보 처리 여부 새로고침 표시 문제 수정

## 확인된 원인

- 실제 데이터베이스에는 `개인정보 처리 여부` 선택값이 정상 저장되어 있습니다. 최근 기록에서도 `개인정보를 처리함` 값이 확인됐습니다.
- 저장 함수도 `privacy`를 허용하고 해당 데이터베이스 열에 정상 반영합니다.
- 문제는 **새로고침 후 저장값을 화면 데이터로 바꾸는 과정**입니다. 일반 입력 항목 목록에 `privacy`가 없는데, 변환 함수가 그 목록만 읽기 때문에 저장된 값을 누락합니다.
- 빈 기록 기본값에도 `privacy`가 명시되지 않아, 화면에서는 선택이 풀린 것처럼 보입니다.

## 수정 내용

1. 성장형 기록을 불러올 때 데이터베이스의 `privacy` 값을 화면 데이터에 명시적으로 포함합니다.
2. 빈 성장형 기록에도 `privacy: ""` 기본값을 명시해 화면 상태를 안정적으로 유지합니다.
3. 현재 정상 작동하는 저장 검증과 데이터베이스 구조는 그대로 둡니다. 마이그레이션은 필요 없습니다.
4. 사용자 가이드의 성장형 단계 설명을 현재 7단계 구성에 맞추고, 개인정보 처리 여부가 자동 저장되는 항목임을 반영합니다.

## 확인 방법

- 05 성찰과 성장에서 세 선택지 각각을 선택하고 자동 저장 표시를 기다린 뒤 새로고침해 선택이 유지되는지 확인합니다.
- 기존에 이미 저장된 기록을 새로고침했을 때 저장값이 바로 표시되는지 확인합니다.
- 개인정보 항목을 포함해 작성률이 정상 계산되는지 확인합니다.
- 다른 성장형 입력과 도전형 활동기록의 저장 동작에 변화가 없는지 확인합니다.

## 기술 메모

- `src/lib/record-growth.functions.ts`: `toDTO` 반환값에 `privacy`를 데이터베이스 열에서 직접 읽어 추가합니다.
- `src/lib/record-growth-schema.ts`: `GROWTH_EMPTY`에 `privacy` 빈값을 명시합니다.
- `src/routes/_main.guide.tsx`: 성장형 활동기록 설명을 현재 단계 구성과 저장 동작에 맞게 갱신합니다.
- 선택값은 이미 데이터베이스에 있으므로 기존 기록 복구 작업은 필요 없습니다.
