# 활동기록 '작성자' 칸 개선 (수정안)

## 무엇이 바뀌나
- 기록 행을 **새로 추가할 때만** 로그인한 닉네임이 작성자 칸에 자동으로 채워집니다. 이후 사용자가 자유롭게 수정하거나 지울 수 있고, 다시 덮어쓰지 않습니다.
- 이미 저장된 기존 행의 빈 작성자는 그대로 둡니다(임의 변경 없음).
- 작성자 칸에 `기록한 사람` 라벨을 붙이고, 플레이스홀더를 `예) 김수학 (수정 가능)`으로 바꿔 용도를 명확히 합니다.
- 사용자 가이드에 "팀 멤버가 행을 추가하면 내 닉네임이 자동 입력되며 수정 가능" 안내를 추가합니다.

## 왜 이 방식인가
행이 화면에 나타난 뒤 자동 채우는 방식은 빈 행 저장 1회 + 작성자 저장 1회로 저장이 두 번 발생하고, 사용자가 일부러 비운 값을 다시 덮어쓸 위험이 있습니다. 생성 시점에만 채우면 저장 횟수는 그대로이고 사용자의 수정 의도도 보존됩니다.

## 기술 메모
- `src/components/RecordEditor.tsx`
  - `emptyRowVars`의 기본 `rowAuthor: ""`는 그대로 둡니다. `StanceSection` 등 다른 곳에서 이 값을 재사용해도 작성자가 들어가지 않도록 합니다.
  - `RowSection`에 `defaultAuthor: string` prop을 추가합니다. 부모 `RecordEditor`에서 공통으로 전달하는 `rowSectionProps` 객체를 만들고, 현재 사용자가 해당 팀의 멤버(`isMember`)이면 `identity?.author ?? ""`를, 아니면 `""`를 `defaultAuthor`로 넣어 전달합니다.
  - **작성자 자동 채움은 `kind`가 `process`(문제 정의 과정 기록)와 `devlog`(자유 개발 기록)인 섹션에만 적용합니다.** 기능·흐름·계획 등 작성자가 의미 없는 행에는 이름이 노출되지 않도록 `defaultAuthor`를 `""`로 둡니다.
  - `RowSection`의 “추가” 버튼 핸들러에서 `emptyRowVars(...)`를 펼친 뒤 `rowAuthor`를 `defaultAuthor`로 덮어씁니다. 이렇게 하면 첫 저장에 작성자가 함께 들어가며, 빈 행 저장 후 다시 채우는 2회 저장 문제가 생기지 않습니다.
  - `RowItem`에는 자동 주입 `useEffect`를 넣지 않습니다. 사용자가 작성자를 지우거나 수정해도 다시 덮어쓰지 않습니다.
  - 작성자 `Input` 앞에 `<Label>기록한 사람</Label>` 추가, 플레이스홀더 문구를 `예) 김수학 (수정 가능)`으로 변경합니다.
- `src/routes/_main.guide.tsx`: 활동기록 섹션에 “과정 기록·자유 개발 기록 행을 추가하면 팀 멤버의 닉네임이 자동 입력되며, 필요하면 수정하거나 지울 수 있어요” 안내를 추가합니다.

## 영향 없음 확인
- DB 스키마·RLS·GRANT 변경 없음, 서버 요청 수 변화 없음.
- `src/lib/record-readme.ts`의 작성자 출력 로직은 그대로 동작합니다.
