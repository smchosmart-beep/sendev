# 투표 종료 후 탈락 게시글까지 전체 순위로 표시

## 문제

결선 종료 화면에는 1차 확정 팀(1~10위)과 결선 후보(11위~16위)만 나오고, 1차에서 탈락한 나머지 게시글은 목록에서 아예 빠집니다. 36개 중 12개를 뽑았다면 17위 이후 게시글도 순위와 득표수와 함께 아래에 이어서 보여야 합니다.

원인(`src/components/VoteSection.tsx` 확인 완료):
- `runoffPosts`(166-169행)가 결선 라운드에서는 결선 후보만 남깁니다.
- 종료 후 목록 `ordered`(197-201행)는 `확정 팀 + 결선 후보`뿐이라 탈락 글이 포함되지 않습니다.

## 수정 내용

1. 결선 종료 화면 목록을 세 묶음으로 구성합니다.
   - ① 1차 확정 팀 → ② 결선 후보 → ③ 그 외 탈락 게시글
2. 탈락 게시글은 자신이 마지막으로 표를 받은 라운드(사실상 1차)의 득표수 기준 내림차순으로 정렬하고, 순위는 앞 그룹에 이어서 매깁니다(예: 17위, 공동 18위 …).
3. 0표 글도 목록에는 표시하되, 지금 규칙대로 순위 배지는 붙이지 않습니다.
4. 탈락 글에는 "선발" 배지와 "이전 라운드 확정" 배지를 붙이지 않고, 득표수만 표시합니다.
5. 결선 **진행 중**에는 지금처럼 결선 후보만 보여 투표 대상 혼동을 막습니다.
6. 1라운드만 진행한 게시판은 이미 전체 글이 보이므로 동작 변화 없음.

## 기술 세부

`src/components/VoteSection.tsx`만 수정(서버·DB 변경 없음, 추가 쿼리 없음):
- `eliminatedOrdered` 추가: `showFinal`일 때 `posts`에서 `lockedIds`·`runoffIds`에 없는 글을 골라 `lockedInfoOf(id).count`(마지막 득표 라운드 표 수) 내림차순 정렬.
- `ordered = [...lockedOrdered, ...runoffOrdered, ...eliminatedOrdered]`.
- `rankMap`: 기존 `rankGroup` 누적 offset 구조를 그대로 사용해 결선 후보 그룹 뒤에 탈락 그룹을 `lockedCountOf` 기준으로 한 번 더 호출.
- 카드 렌더링: 득표수 표기 조건을 `showFinal && isLocked` → `showFinal && !runoffIds.has(post.id)`로 넓혀 탈락 글도 이전 라운드 득표수를 보이게 함. "이전 라운드 확정" 배지 조건은 `isLocked` 그대로 유지.
- 페이지네이션은 기존 `PAGE_SIZE` 로직 그대로(총 글 수가 늘어 페이지가 추가될 수 있음).

## 부작용 검토

- 서버 요청·쿼리 수 변화 없음(이미 받아 둔 `posts`, `roundCounts`만 사용).
- 투표 진행 중 화면은 완전히 동일.

## 추가 요청: 이전 라운드 확정 팀의 투표자 명단 표시

현재 투표자 명단(관리자에게만 보임)은 **현재 라운드 표만** 담고 있습니다(`platform.functions.ts` 4626-4630행: `rd !== cfg.round`이면 건너뜀). 그래서 결선 종료 화면에서 1차 확정 팀 카드에는 명단이 비어 있습니다.

### 수정 내용

- 확정 팀 카드에도 그 팀이 확정된 라운드(1차)의 투표자 명단을 표시합니다.
- 17위 이후 탈락 글도 같은 방식으로 자신이 표를 받은 라운드의 명단을 표시합니다.
- 명단 노출 권한은 지금과 동일하게 **관리자만**입니다(일반 사용자에게는 표시되지 않음).

### 기술 세부

- `platform.functions.ts` `getVoteResults`: 이미 라운드 필터 없이 읽고 있는 같은 쿼리에서 `roundVoters: Record<round, Record<postId, string[]>>`를 관리자일 때만 추가로 채워 반환(쿼리 추가 없음). `VoteResultsDTO`에 선택 필드로 추가하고 기존 `voters`는 그대로 유지.
- `VoteSection.tsx`: 명단 조회를 `showFinal && !runoffIds.has(post.id)`인 경우 `roundVoters[lockedInfoOf(post.id).round]?.[post.id]`에서, 그 외에는 기존 `voters[post.id]`에서 가져오도록 헬퍼로 정리.

### 부작용

- 쿼리 수·DB 변경 없음. 응답 크기는 관리자 요청에서만 소폭 증가.
- 비관리자 응답은 완전히 동일.
