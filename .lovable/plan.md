# 03·04 단계에 작성 현황 사이드바 추가

내용이 많은 **03 최종 결과물**과 **04 개발·교육적 점검** 단계에 오른쪽 사이드바를 붙여, 블록 목록 클릭으로 바로 이동하고 각 블록의 작성 현황을 한눈에 보이게 합니다. 레퍼런스의 번호 뱃지 + 제목 + 상태 라벨 구조를 따르되, 색·모서리·그림자는 지금 sendev 톤(`rounded-2xl`, `bg-card`, 시맨틱 토큰, 은은한 그림자)을 그대로 씁니다.

## 화면

```text
[ 본문 블록들 (기존 그대로) ]        [ 작성 현황 ]
  01 소개                              전체 3/9 작성
  02 링크                              01 소개      작성됨
  03 핵심 기능                         02 링크      작성중
  ...                                  03 핵심 기능  미작성
```

- 데스크톱(lg 이상): 본문 왼쪽 + 사이드바 오른쪽(약 260px), 사이드바는 스크롤을 따라 고정(sticky).
- 모바일/태블릿: 사이드바가 본문 위쪽에 접이식 카드로 표시되고, 헤더에 "3/9 작성"만 요약해 보여 줍니다.
- 항목 클릭 시 해당 블록으로 부드럽게 스크롤하고, 스크롤 위치에 따라 현재 블록이 강조됩니다.

## 각 단계 블록 목록

**03 최종 결과물**: 소개 / 링크 / 핵심 기능 / 사용 흐름 / 기술 구성과 실행 / 라이선스와 출처 / 현재 한계 / 다음 계획 / 만든 사람

**04 개발·교육적 점검**: 자유 개발 기록 / 바꾼 판단 / 막혔던 순간 / 교사와 학생의 자리 / AI 활용과 확인 / AI 실수 검증 / 입력·전송·저장 / 위험·대응·검증

## 상태 표시

- **미작성**: 해당 블록에 아무 값도 없음 (흐린 회색)
- **작성중**: 일부만 채워짐 (앰버 계열 토큰)
- **작성됨**: 필수 항목이 모두 채워짐 / 행이 1건 이상 (프라이머리 계열)

행 기반 블록은 행 수(`2건`)를, 필드 기반 블록은 채운 칸 수(`3/6`)를 상태 옆에 작게 덧붙입니다.

## 기술 메모

- 새 컴포넌트 `src/components/record/StepSidebar.tsx`: `{ id, no, title, status, meta }[]`와 현재 활성 id를 받아 렌더링. 스크롤 감시는 `IntersectionObserver`로 처리하고 클릭 시 `scrollIntoView({ behavior: "smooth", block: "start" })`.
- `src/components/RecordEditor.tsx`의 `step === 2` / `step === 3` 렌더 블록을 `lg:grid lg:grid-cols-[minmax(0,1fr)_260px]` 레이아웃으로 감싸고, 각 `<section>`에 `id`와 `scroll-mt-24`를 부여합니다.
- 상태 계산은 순수 함수로 분리(`src/lib/record-progress.ts`): 03은 `final` 필드 그룹별 채움 여부, 04는 `rows`의 kind별 건수 + `RISK_GROUP` 필드 채움 여부를 사용합니다. 이미 있는 `record-readme.ts`의 3단계(`empty`/`partial`/`done`) 판정 기준과 라벨을 동일하게 맞춥니다.
- 데이터 소스는 이미 로드된 `bundle`과 `final` 로컬 상태뿐이라 추가 서버 요청·쿼리·마이그레이션이 없습니다. 저장 로직과 07 출력 보기 판정에는 손대지 않습니다.
- 사이드바는 인쇄/출력 영역과 무관하므로 `record-output-ui` 계열 클래스와 충돌하지 않게 별도 래퍼로 둡니다.
