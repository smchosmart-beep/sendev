# 02 문제 정의 과정 — 전용 탭 입력칸이 사라진 문제 수정

## 무엇이 잘못됐나

"그 밖의 문제 정의 메모" 탭에만 추가 버튼을 남기도록 바꾼 뒤,
[22일 팀빌딩·문제 정의 회의], [인터뷰 기록], [인터뷰 후 문제 구체화 회의]
세 탭은 **기록 줄을 만들 방법이 사라졌습니다**. 이 탭들은 저장된 줄이 있어야
입력칸이 그려지는 구조라, 아직 아무것도 쓰지 않은 팀에게는
"아직 등록된 내용이 없어요."만 보입니다.

## 어떻게 고칠까

세 탭은 각각 **정해진 한 벌의 양식**이므로, 줄을 추가하는 개념 없이
탭을 누르면 **바로 그 양식의 입력칸이 펼쳐지도록** 합니다.

- 전용 양식 탭을 열었을 때 그 탭의 기록이 아직 없고 편집 권한이 있으면,
  **빈 양식 한 벌을 화면에만 바로 표시**합니다. 내용을 채우고 [저장]을
  눌러야 실제 기록으로 저장되며, 그냥 지나가면 아무것도 남지 않습니다.
- 편집 권한이 없는 방문자에게는 지금처럼 "아직 등록된 내용이 없어요."만
  보입니다.
- 추가 버튼은 기존 요청대로 **"그 밖의 문제 정의 메모" 탭에만** 유지합니다.
- 내용이 하나도 없는 빈 기록은 **README 출력·사례집 출력에서 제외**하고,
  **작성 현황(미작성/작성중/작성완료) 계산에서도 함께 제외**합니다.
  (예전에 빈 줄만 만들어 둔 팀은 해당 항목이 '작성완료'에서 정확한 상태로
  바뀝니다.)

## 기술 메모

- `src/components/RecordEditor.tsx`
  - `RowSection`: 선택 탭에 `PROCESS_SUBTYPE_TEMPLATES` 전용 양식이 있고
    그 탭 행이 0개이며 `canEdit`이면, 저장되지 않은 임시 행을 만들어
    `RowItem`으로 렌더링. 임시 행은 `id: null`, `knownUpdatedAt: ""`,
    `subtype: 선택탭`으로 구성하고(서버 검증이 `id`를 uuid 또는 null만
    허용), 삭제 버튼은 숨김.
  - 저장 버튼은 기존 `dirty` 판정을 그대로 써서 빈 행 저장을 막음.
  - 추가 버튼 노출 조건(`selectedSubtype === defaultSubtype`)은 유지.
- `src/lib/record-readme.ts`
  - 행 렌더 루프(`buildRecordReadme`)에서 col1~col6이 모두 공백인 행 제외.
  - `getPublicReadmeBlocks`의 `rowsOfKind` 집계도 같은 기준으로 빈 행 제외해
    출력과 상태 표시를 일치시킴.
- `src/components/record/CasebookDocument.tsx`: 같은 빈 행 제외 기준 적용
  (섹션 노출 여부 판정 포함).
- `src/routes/_main.guide.tsx`: 02 단계 설명에 "전용 탭은 누르면 바로 양식이
  열리고, 줄 추가는 '그 밖의 문제 정의 메모' 탭에서만 한다" 반영.

서버 함수·DB 스키마 변경 없음, 추가 네트워크 요청 없음.
