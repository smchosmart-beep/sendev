# 해커톤 후기 담벼락 좌우 폭 문제 — 실측 후 수정

## 배경

노트북 화면에서 좌우 후기 담벼락의 폭이 달라 보이고, 오른쪽 카드가 잘려 보입니다.
다만 코드상 좌우는 같은 폭 계산식(`50% - 33rem`)을 쓰고 있어 **비대칭 원인은 아직 확정되지 않았습니다**.
따라서 먼저 실측하고, 그 결과에 따라 고칩니다.

## 1단계: 실측 (수정 전 확인)

해커톤 탭이 열린 실제 화면에서 좌/우 담벼락 컨테이너의 위치·폭을 측정합니다.

- 확인 항목: 뷰포트 폭, 좌 패널 `x`/`width`, 우 패널 `x`/`width`, 내부 2개 열의 실제 폭
- 판정:
  - 좌우 `width`가 같다 → 비대칭이 아니라 **폭 부족으로 인한 카드 잘림** 문제 → 2단계만 적용
  - 좌우 `width`가 다르다 → 위치 지정 방식을 중앙 기준 inset으로 교체 → 3단계도 적용

## 2단계: 좁은 폭 대응 (주 수정)

현재 패널 폭 = `50% - 33rem`이라 화면이 좁을수록 급격히 줄어듭니다.

- 1440px 노트북: 한쪽 약 192px → 2열이면 열당 약 92px
- 1309px 미리보기: 한쪽 약 126px → 열당 약 59px (사실상 표시 불가)

수정 내용:

- **담벼락 노출 기준은 `xl`(1280px) 그대로 유지** — 좁은 화면에서도 완전히 사라지지 않도록 합니다.
- 화면 폭에 따라 내부 열 수를 조정:
  - **`1280px ~ 1536px`**: 1열로 렌더
  - **`1536px 이상`**: 2열 유지
- 카드 컨테이너에 `min-w-0` 추가해 긴 단어로 인한 밀림·잘림 방지
- 1열/2열 전환 시에도 좌우 패널의 카드 분배 로직(애니메이션 on/off 기준 등)은 동일한 구조를 유지하되, 열 단위가 하나로 합쳐질 때 카드 수에 따른 애니메이션 판정이 자연스럽게 이어지도록 처리

## 3단계: 대칭 보정 (1단계에서 차이가 확인될 때만)

`w-[calc(50%-33rem)]` + `left-1`/`right-1` 방식을 중앙 기준 inset으로 교체합니다.

- 좌: `left-1 right-[calc(50%+33rem)]`
- 우: `right-1 left-[calc(50%+33rem)]`

이렇게 하면 본문(`max-w-5xl`)으로부터의 시작 거리가 좌우 동일해지고, 남는 공간을 화면 끝까지 사용합니다.

## 영향 범위 / 안전성

- 변경 파일: `src/components/HackathonReviews.tsx` (CSS 클래스만)
- 데이터·권한·쿼리·서버 함수 변경 없음 → 서버 비용 및 기존 기능 영향 없음
- 모바일 하단 가로 마퀴 스트립은 손대지 않음

## 기술 세부

- 대상: `HackathonReviewSideColumns` 내부 `wall()` (약 493-516행)와 `marqueeColumn()`
- 실측은 미리보기 브라우저에서 `getBoundingClientRect()`로 수행
- 열 개수 분기는 `colA`/`colB` 분배 로직을 조건부로 하나의 배열로 합치는 방식으로 처리
