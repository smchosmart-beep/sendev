## 04 화면 상세 (원본 문구 그대로)

**머리말** — "내 앱을 세 번 점검합니다. 자기 점검 → AI 점검 → 동료 점검 순서로 진행하고, 점검마다 무엇을 어떻게 고쳤는지 남깁니다." / 오른쪽에 `n / 3 점검`

**1차 · 자기 점검**
- 안내: "01~03에 적은 내용이 이 앱의 PRD입니다. 기억이 아니라 기록과 실제 화면을 비교합니다."
- 체크리스트 6줄: 한 줄 소개대로 동작하는가 / 주 사용자가 설명 없이 첫 화면에서 할 일을 아는가 / 핵심 기능 ①②③ / 사용 흐름 1→2→3이 끊기지 않고 통과되는가 — 각 줄에 01~03에 적은 값을 함께 보여 줌
- 완성 상태 제안: '안 됨'이 하나라도 있으면 `아이디어`, 기능 중 '화면만'이 있으면 `시연 가능`, 모두 '됨'이면 `바로 사용 가능 후보`. "제안만 표시합니다. 03의 값은 직접 바꿔 주세요."
- 접었다 펴는 `안 되는 길도 걸어 보기`(선택) 6개 관점
- '문제 있음'이 있으면 "문제 있음으로 표시한 것 중 하나를 골라 고치고 아래에 남겨 주세요." 안내
- 아래에 수정 기록

**2차 · AI 점검**
- 안내: "AI가 내 기록을 읽고 질문합니다. 답하지 못한 질문이 곧 고칠 곳입니다." / `질문 받기` 버튼
- 질문 5개: 공통 3개 + 02에서 고른 문제 영역에 맞는 2개(수업·평가 / 생활교육·상담 / 행정·업무 효율화 / 학교 소통·협업 각각 별도 질문). 버튼을 누를 때마다 하나씩 열리고 5개를 넘기면 처음부터 다시 봅니다.
- `답함 n / 5`, `답하지 못함 n`, 문제 영역 표시
- `오류가 나면 이 다섯 단계만`: 재현 / 증거 확인 / 분류 / 최소 수정 / 재검증
- 수정 기록 제목은 "답하지 못한 질문 중 하나를 골라 고칩니다."

**3차 · 동료 점검**
- 안내: "짝은 무작위로 정해집니다. 마주 앉아 설명하지 않고, 링크만 열어 직접 써 봅니다." / `짝 배정 받기` 버튼(같은 성장형 게시판의 다른 사람 기록 중 2명, 본인 제외)
- 짝 카드: 이름, 프로젝트명, 한 줄 소개, `배포 주소 열기`, `01~03 기록 보기`(핵심 기능·사용 흐름)
- `01 내가 남기는 피드백`: 기대한 것 / 실제로 나온 것(각 120자) → `보내기`(보낸 뒤 `다시 전달하기`, `전달됨` 표시)
- `02 내가 받은 피드백`: 보낸 사람·기대·실제와 함께 `오늘 고침 · 다음에 · 고치지 않음` 분류
- "판단이 아니라 관찰을 건넵니다. 무엇을 고칠지는 만든 사람이 정합니다."
- 아래에 수정 기록

## 기술 메모

- DB 변경 없음. `record_growth.review`(jsonb)의 내용 구조만 교체합니다.
  - 새 구조: `{ self: { checks, angles, fix }, ai: { revealed, questions[{q,a,unanswered}], fix }, peer: { assigned[], given[], received-분류, fix } }`, `fix = { what, how, skipped, type }`
  - 읽기 시 이전 구조(`selfChecks`/`aiChecks`/`sharedFixes`)는 무시하고 빈 값으로 시작하도록 관대하게 파싱합니다. 성장형 기록은 아직 실사용 데이터가 없어 손실 위험이 없고, 도전형 데이터는 전혀 건드리지 않습니다.
  - 동료 피드백은 지금처럼 `record_growth_peer_feedback` 테이블로 실제 전달하고, 받은 쪽 분류는 `receiver_type`에 저장합니다(그대로 사용).
- `src/lib/record-growth-schema.ts`: 자기 점검 체크리스트 키·관점 목록·AI 공통 질문 3개·문제 영역별 질문 2개씩·수정 기록 필드·완성 상태 제안 규칙을 정의. `GROWTH_REQUIRED.review`는 `n / 3 점검` 기준(세 점검의 fix 완료: 고친 것·어떻게 고쳤나·분류)으로 교체
- `src/lib/record-growth.functions.ts`: `review` 검증 스키마를 새 구조로 교체, 저장/조회는 기존 인증(작성자 본인 또는 관리자)·1초 지연 자동 저장 유지. 동료 배정/전송 함수의 권한 확인과 보낸 피드백의 상대 이름 표시도 함께 정리
- `src/components/record/GrowthRecordEditor.tsx`: 04를 `Tabs`(shadcn) 기반 `ReviewStep`으로 재작성 — `SelfPanel` / `AiPanel` / `PeerPanel` / 공통 `FixBlock`. 좌우 방향키 이동과 탭 완료 체크 표시 포함
- `GrowthReadmeOutput.tsx`, `GrowthCasebookDocument.tsx`, `GrowthAdminPanel.tsx`를 새 구조에 맞게 수정
- 도전형(활동기록) 코드와 `/guide`, 나눔·온라인 갤러리 화면은 이번에도 건드리지 않습니다.
