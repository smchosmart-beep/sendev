# 게시판별 글 작성 템플릿 (관리자 등록) — 코드 확인 후 수정본

관리자가 카테고리별·유형별로 글 작성 템플릿을 등록해 두면, 사용자가 글쓰기 화면에 들어갔을 때 본문 편집기에 그 내용이 미리 채워집니다.

## 검토로 바뀐 점 (실제 코드 확인 결과)

- **본문이 있는 유형은 3개뿐**: 산출물·링크·문제ZIP 등록 폼에는 본문(content) 입력 자체가 없습니다(`new-project.tsx`, `new-link.tsx`, `new-problem.tsx`에 `content` 상태 없음). → 템플릿 대상은 **일반글(공지 포함) / 질문 / 투표** 3종으로 축소합니다.
- **편집기는 서식 있는 편집기(HTML 저장)**입니다(`PostEditor.tsx:331,349` TipTap). 관리자 화면에서도 일반 텍스트 상자가 아니라 **같은 편집기(PostEditor)** 로 템플릿을 작성해야 줄바꿈·서식이 그대로 재현됩니다.
- **카테고리 목록은 사이트 전역에서 쓰이는 공용 쿼리**이고 컬럼을 명시적으로 나열합니다(`platform.functions.ts:291`). 템플릿 본문을 여기에 넣으면 모든 페이지 응답이 커집니다. → 템플릿은 **글쓰기 화면에서만 따로 가져오는 전용 조회**로 분리합니다.

## 동작

- 관리자 > 카테고리 편집에 "글 작성 템플릿" 섹션 추가: 일반게시판 / 질문 / 투표 각각 편집기 1개. 해당 유형이 꺼져 있으면 숨김.
- 비워두면 지금과 동일하게 빈 본문으로 시작합니다.
- 템플릿이 있으면 글쓰기 페이지 진입 시 본문 편집기에 **1회만** 채우고, 사용자가 자유롭게 고치거나 지울 수 있습니다.
- 연재(다음 편 작성)에도 동일하게 적용(빈 본문에만 채움).
- 예시 문장([누구]/[어떤 상황]/[근본 원인]/[구체적 고통(QQQ)])은 기본값으로 넣지 않고 관리자 화면에서 직접 등록합니다.

## 기술 메모

1. **마이그레이션**: `categories`에 `template_post`, `template_question`, `template_vote` (`text not null default ''`) 추가. 신규 테이블 없음 → GRANT/RLS 변경 없음(기존 카테고리 접근 경로 그대로).
2. **서버 함수** (`src/lib/platform.functions.ts`)
   - 신규 `getPostTemplate({ categoryId, type })` — 해당 컬럼 1개만 select 해서 문자열 반환. 공용 카테고리 select(291행)는 **변경하지 않음**.
   - `updateCategory` / `createCategory` 입력 스키마에 세 필드 추가(`z.string().max(8000).optional()`) 및 patch 반영.
   - 관리자 편집 화면용 조회에만 템플릿 값 포함(`getCategoryTemplates({ categoryId })` 또는 위 함수 재사용).
3. **쿼리** (`src/lib/platform.queries.ts`): `postTemplateQueryOptions(categoryId, type)` 추가, `staleTime` 넉넉히(예: 5분) — 글쓰기 페이지 진입당 최대 1회 호출.
4. **글쓰기 폼**: `new-general.tsx`, `new-question.tsx`, `new-vote.tsx`에서 위 쿼리를 사용해 값이 도착하면 `content`가 비어 있을 때만 한 번 설정(`useEffect` + `appliedRef`). 사용자가 지운 뒤 다시 채워지는 일이 없도록 플래그로 1회 제한.
5. **관리자 화면** (`src/routes/admin.categories.tsx`): 편집 다이얼로그에 접이식 "글 작성 템플릿" 섹션 + `PostEditor` 3개, 저장 시 기존 mutation 페이로드에 포함.
6. **가이드** (`src/routes/_main.guide.tsx`): 글쓰기 항목에 "게시판에 따라 본문에 작성 양식이 미리 채워질 수 있고 자유롭게 고칠 수 있음", 관리자 항목에 등록 위치 안내 추가.

## 부작용 검토 결과

- **회귀 위험 없음**: 템플릿이 빈 문자열인 기존 게시판은 동작이 그대로입니다. 공용 카테고리 쿼리를 건드리지 않아 목록·헤더·탭 등 다른 화면 영향 없음.
- **서버 비용**: 글쓰기 페이지 진입 시 작은 조회 1회(캐시됨). 루프·폴링 없음. 600명 동시 참여 상황에서도 무시할 수준.
- **데이터 안전성**: 컬럼 추가만 있고 삭제·변경 없음. 기존 글 데이터 영향 없음.
- **권한**: 템플릿 편집은 기존 `updateCategory`의 관리자 비밀번호 검증 경로를 그대로 사용합니다(신규 공개 쓰기 경로 없음).
- **미확인**: 관리자 편집 다이얼로그의 현재 레이아웃이 편집기 3개를 넣기에 충분한지는 구현 중 확인해 접이식으로 처리합니다.
