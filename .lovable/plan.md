# 활동기록 입력칸에 예시 플레이스홀더 추가

작성 부담을 줄이기 위해 활동기록 에디터의 거의 모든 입력칸에 "이렇게 쓰면 돼요" 수준의 예시 문구를 회색 플레이스홀더로 넣습니다. 실제 저장값에는 영향이 없고, 비어 있을 때만 보이는 안내 문구입니다.

## 어디에 무엇이 들어가나

**01 팀 공통정보**
- 팀원 닉네임: `예) 김수학`
- 소속: `예) ○○초등학교 5학년` / 역할: `예) 기획·문제 정의`

**02 문제 정의 과정**
- 언제·어디서: `예) 4/12 방과후 교실`
- 무엇을 나눴나요?: `예) 5학년 학생들이 배수 판별에서 자주 틀리는 지점을 이야기했어요.`
- 그래서 정한 것: `예) 3의 배수 판별 연습을 먼저 만들기로 했어요.`

**03 최종 결과물**
- 서비스 이름 `예) 배수 판별 연습기`, 한 줄 소개 `예) 3·4·9의 배수를 스스로 확인해 보는 연습 도구`
- 태그 `예) 초등수학, 배수, 연습`
- 문제/해결: `예) 학생들이 판별법을 외우기만 하고 이유를 몰랐어요.`
- 사용 환경 `예) PC 웹, 모바일 웹`, 배포 주소 `예) https://내서비스.lovable.app`, GitHub·시연 영상 주소도 URL 예시
- 사용 조건 `예) 계정 없이 무료로 사용할 수 있어요.`
- 기술 구성(화면/서버/AI/저장소/배포), 폴더 구조, 설치·실행 명령, 환경변수 이름 각각 예시
- 라이선스 `예) MIT`, `예) CC BY 4.0`, 외부 자료 출처 예시
- 핵심 기능 / 사용 흐름 / 현재 한계 / 다음 계획 / 제작자와 담당 표의 각 열에도 예시

**04 개발·교육적 점검**
- 개발 기록(날짜/무슨 일/어떻게 해결), 바꾼 판단, 막혔던 순간, AI 활용, AI 실수 사례, 개인정보 항목표의 모든 열에 예시
- 태도 점검 한 줄 설명: `예) 학생 이름 대신 번호만 쓰도록 바꿨어요.`
- 변화와 위험 점검(확인 범위, 변화 내용, 예상 위험, 줄이려 한 일, 멈춤 기준, 검증 방법) 각각 예시

**05 개인 후기·소회**
- 소속·역할, 기억에 남는 순간, 배운 점과 남은 질문, 약속 실천 방법, 나눌 계획에 예시

## 기술 사항

- `src/lib/record-schema.ts`의 `RowSectionDef`에 선택 필드 `placeholders?: string[]`(열 순서와 1:1)를 추가하고 각 섹션 정의에 예시 문구를 채웁니다.
- `src/components/RecordEditor.tsx`
  - `RowSection` → `RowItem`으로 `placeholders`를 전달하고, `Input`/`Textarea`에 `placeholder={placeholders?.[i]}`를 적용합니다. `cols`를 덮어쓰는 호출부(process, devlog)는 함께 `placeholders`도 전달합니다.
  - `FinalInput` 타입에 `placeholder?: string`를 추가하고 `FINAL_GROUPS` / `RISK_GROUP` 각 필드에 예시를 채워 `FinalField`에서 사용합니다. `select`/`image` 타입은 해당 없음.
  - `MemberRow`, `StanceItem`, `ReflectionSection` 입력칸에 직접 `placeholder`를 넣습니다.
- 저장 로직, 서버 함수, DB, README 출력 로직은 손대지 않습니다(플레이스홀더는 값이 아니므로 상태 판정에도 영향 없음).
- 가이드(`src/routes/_main.guide.tsx`) 활동기록 안내에 "각 칸의 회색 예시 문구는 참고용이며 저장되지 않아요" 한 줄을 추가합니다.
