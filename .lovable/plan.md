# 교육적 태도 점검 — 선택 방식을 드롭다운 4항목으로 변경

## 목표

04 개발·교육적 점검 단계의 [교육적 태도 점검]에서 **해당함 / 해당 없음** 버튼 두 개를 없애고, 같은 자리에 드롭다운 하나를 놓습니다. 선택 항목은 아래 네 가지입니다.

1. 원래 그렇게 했어요
2. 점검하다 고쳤어요
3. 아직이에요
4. 우리 프로그램엔 해당 없어요

동작은 지금과 같습니다: 선택하면 바로 저장되고, 아래 한 줄 설명은 [저장] 버튼으로 저장됩니다.

## 화면 변경

- 문항마다 버튼 두 개 대신 드롭다운(선택 컴포넌트) 하나를 표시. 모바일 폭에서도 한 줄에 들어가도록 전체 너비로 배치.
- 아직 고르지 않은 문항은 "선택해 주세요" 안내 문구가 보이고, 진행 배지 계산(문항 4개 중 몇 개 응답)은 지금 로직 그대로 유지.
- 미선택 상태는 빈 값을 SelectItem으로 만들지 않고, `value={choice || undefined}` + `<SelectValue placeholder="선택해 주세요" />` 방식으로 처리합니다.
- 편집 권한이 없을 때는 드롭다운이 비활성 상태로 값만 보이도록 유지.

## 기존 데이터 처리

현재 데이터베이스에는 옛 값(`해당함`, `해당 없음`)으로 저장된 응답이 2건 있습니다. 데이터는 지우거나 변환하지 않고 그대로 둡니다.

드롭다운은 기본적으로 4개 신규 항목만 보여주되, 저장된 `choice` 값이 4개 항목에 없을 때만 해당 값을 임시 `SelectItem`으로 추가해 함께 노출합니다. 예: `해당함 (이전 표기)`. 값 자체는 원문을 그대로 유지하며, 사용자가 다른 항목을 고르면 그때 새 값으로 덮어써집니다.

## 출력물과 가이드

- README와 사례집 PDF는 저장된 응답 문구를 그대로 쓰므로 별도 수정 없이 새 문구가 그대로 나옵니다.
- 관리자 현황(응답 개수 배지, 엑셀)도 값의 존재 여부만 보므로 변경 없음.
- 사용자 가이드(`/guide`)의 04단계 설명에서 "해당함 · 해당 없음 중 하나를 고른다"는 문구를 새 네 항목 드롭다운 설명으로 교체.

## 기술 메모

- `src/lib/record-schema.ts`: `STANCE_CHOICES`를 네 항목으로 교체.
- `src/components/RecordEditor.tsx`의 `StanceItem`: 버튼 매핑을 shadcn `Select`로 교체하고, `onValueChange`에서 기존 `save(choice, memo)` 호출을 그대로 사용. 저장 스키마(`col1` = 선택, `col2` = 설명)는 변경 없음.
- `StanceItem` 구현 시: `value={choice || undefined}`로 설정해 미선택 상태를 placeholder로 처리하고, `choice`가 4개 항목에 없으면 임시 `SelectItem`으로 원문을 함께 노출합니다.
- 사례집 PDF의 응답 칸이 좁아 "우리 프로그램엔 해당 없어요" 등이 두 줄로 줄바꿈될 수 있으나, 표가 깨지지는 않으므로 그대로 둡니다.
- 서버 함수, 마이그레이션, 테이블 변경 없음.
